# Общие правила взаимодействия

[К обзору фичи](README.md)

**Статус:** основные правила списка и доступа согласованы; конкретные команды и оформление обратной связи обсуждаются. Предложения по UI отмечены отдельно.

## Требования к хранилищу

На уровне дизайна меню должно получать сведения о предметах, их количестве, свойствах для отображения и реальных местах хранения. Оно должно позволять выполнять разрешённые действия с соблюдением ограничений конкретного хранилища. Технический способ получения сведений и выполнения действий выбирается при реализации.

Количество содержимого и вместимость — разные сведения. Ванильные слоты и кейсы сохраняют свои правила; единый счётчик заполнения x / y предусмотрен только для наших контейнеров. Наличие списка не требует от каждого хранилища такого счётчика.

Меню показывает доступные для конкретного контекста сведения и действия. Например, настройка фильтра относится к хранилищу, где такой функционал предусмотрен; детали настройки фильтров ванильных кейсов остаются открытым вопросом.

Текущая область поддержки — ванильные хранилища и контейнеры нашего мода. Интеграции с другими модами пока не рассматриваются. Требования описывают взаимодействие, а не вводят технический API или автоматическое подключение любых объектов.

## Общие правила взаимодействия

- Список представляет реальные запасы и не создаёт отдельного хранилища.
- Открытие меню не запускает сортировку. Без включённой автоматизации предмет остаётся там, куда его положил игрок, если помещение допустимо.
- Поиск и список рекурсивно охватывают всю допустимую вложенность в выбранной области. Это не разрешает новые способы физического размещения.
- Помещение и получение соблюдают ограничения получателя. Общий список не обходит вместимость, фильтры, специализацию или ванильные слоты и стаки.
- Изменение фильтра сохраняет уже лежащие вещи видимыми и доступными для получения.
- Группировка строк действует одинаково в обоих контекстах и не меняет сами предметы.
- Локальное меню не означает разрешения на удалённое получение по всей подлодке.

Правила [вложенности](../container/README.md#слоты-и-вложенность), [помещения и извлечения](../container/README.md#помещение-и-извлечение-предметов) и [фильтров](../container/README.md#фильтры) описаны у контейнера. Запуск [автосортировки](../automation/README.md) из меню пока обсуждается и должен оставаться явным действием опциональной функции.

## Граница между меню и контейнером

**Принято.** Меню отвечает за представление запаса и управление действиями игрока. Контейнер отвечает за хранение, вместимость, допустимость приёма, сохранность содержимого и результат помещения или извлечения. Полноценный сценарий использования нашего контейнера включает меню; контейнер использует эту фичу как способ взаимодействия.

| Ответственность меню | Ответственность контейнера |
| --- | --- |
| Показать предметы, сгруппировать строки и предоставить поиск | Хранить экземпляры с их состоянием и содержимым |
| Дать выбрать действие, количество и место назначения | Принять или выдать допустимое количество предметов |
| Показать заполнение и ограничения | Определить собственную вместимость и правила приёма |
| Предоставить управление фильтром и показать отказ | Применять фильтр, сохранять уже лежащие вещи после его изменения |

Например, игрок запрашивает помещение десяти единиц алюминия. Контейнер определяет, сколько может принять; меню показывает результат. Согласованные правила частичного переноса находятся в [описании контейнера](../container/README.md#помещение-и-извлечение-предметов); конкретные кнопки и формат обратной связи ещё выбираются.

## Общие предложения по UI

- Позволить получать выбранное количество и выбирать конкретный экземпляр при необходимости.
- Показывать фактически выполненный перенос, остаток и причину ограничения.
- Выбирать краткие сведения об экземпляре для строки и подробности для подсказки, не перегружая список; см. [отображение групп](grouping.md#отображение-и-сохранность).
