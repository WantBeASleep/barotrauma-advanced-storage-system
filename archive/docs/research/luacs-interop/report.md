## Карта моста

LuaCs loader → CLR Assembly/Type lookup → UserData registry → descriptor → static userdata или экземпляр → VM index/call → overload binder → ScriptToClr conversion → C# метод → ClrToScript conversion → Lua результат.

Обратный путь: Lua function → Closure или конкретный delegate converter → C# хранит/вызывает callback → Script.Call → DynValue → нужный C# результат. События, Hook и Patch имеют отдельные пути вызова и очистки. [Полная карта с источниками](../../../.codex/skills/luacs-interop/references/bridge.md), [загрузка и жизненный цикл](../../../.codex/skills/luacs-interop/references/lifecycle.md).

## Основные результаты

- **E/S:** собственному DTO не нужен метод `new` или `init`. Зарегистрированный static userdata вызывает constructor через `Type(...)` или `Type.__new(...)`. `init` в Medical Icons — написанная автором фабрика.
- **E/S:** Lua table автоматически превращается в поддерживаемые коллекции по типу параметра, но не в произвольный class DTO. Для DTO нужен настоящий экземпляр либо явный адаптер. Передача в `object` сохраняет table как MoonSharp.Table.
- **E/S:** зарегистрированная коллекция возвращается как userdata с CLR-индексами; незарегистрированный IList может превратиться в Lua table-копию с индексами с 1. Регистрация меняет поведение на уровне общего registry; локальная typed wrapper позволяет не менять его ради одного вызова.
- **E/S:** class сохраняет ссылочную семантику, struct, извлечённый из свойства, — копия. Для изменения состояния владельца требуется обратная запись или C# метод.
- **E/S:** optional, params, ref/out поддерживаются, но имеют конкретные правила. Числа — double, преобразование в int округляет; overload binder не повторяет правила компилятора C#.
- **E/S:** форк поддерживает generic methods с явными типовыми аргументами. Однако закрытие generic-метода не запускает полноценную повторную конверсию: `Echo<int>(3)` может получить double и упасть. Универсальное «generic не поддерживается» тоже неверно.
- **E/S:** Closure и совместимые events позволяют callback C# → Lua. Произвольные Func/Action требуют converter; LuaCs предоставляет конкретный набор. Прямой Closure, GUI converter и event dispatch по-разному обрабатывают ошибки и время жизни.

[Матрица типов и коллекций](../../../.codex/skills/luacs-interop/references/types.md), [сравнение DTO-контрактов](../../../.codex/skills/luacs-interop/references/contracts.md).

## Рекомендации

Для собственного API исходный выбор — небольшой class DTO, типизированный метод с уникальным именем, явная валидация и регистрация вложенных/возвращаемых типов. Это использует проверенную userdata-конверсию, делает ошибку привязанной к конкретной границе и упрощает сопровождение. Конструктор удобен для нескольких обязательных аргументов; фабрика — для инвариантов; заполнение свойств — для большого запроса; Table-адаптер — для строгой проверки Lua-данных до округления и удобного именованного ввода.

Для callbacks выбирай самый короткий достаточный срок жизни. Синхронный Closure не требует хранения; для event нужны исходная функция отписки и владелец очистки; для долгоживущего игрового callback проверь актуальность Script, поток и остановку источника. Это следствие реальных удерживаемых ссылок и разных dispatcher-путей, а не предположение о GC.

Подробные критерии, альтернативы и ограничения: [контракты](../../../.codex/skills/luacs-interop/references/contracts.md), [callbacks](../../../.codex/skills/luacs-interop/references/lifecycle.md). ## Открытые вопросы

- Игровая загрузка demo на клиенте и сервере, реальный stop/reload и длительные event/delegate ссылки требуют отдельного игрового прогона. Полный комплект файлов и ожидаемый результат подготовлены.
- Сборка `0a9af9a…` из папки игры не сопоставлена с доступным commit официальных репозиториев; выводы о новом LuaCs ограничены workshop-сборкой. Перезапись установки не входила в исследование.
- Generic instance/extension/optional/ref/params комбинации не покрыты полностью. При использовании проверь конкретную сигнатуру либо дай обычный C# фасад.
- Не исследована массово внутренняя логика DLL-only модов; не найденные в исходниках подходы не объявлены невозможными.
- Benchmarks не выполнялись. Рекомендации по сокращению копирований основаны на исходниках, а не на измеренном преимуществе по времени.
