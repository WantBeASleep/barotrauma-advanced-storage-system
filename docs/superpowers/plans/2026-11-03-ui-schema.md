# План реализации UI Barotrauma из JSON

> **Для исполнителя:** применять `superpowers:executing-plans` при самостоятельном выполнении либо `superpowers:subagent-driven-development`, если пользователь выберет работу через агентов. Выполнять задачи по порядку, отмечая шаги флажками.

**Цель:** выпустить самостоятельный Lua-пакет, который принимает JSON, создаёт штатный UI Barotrauma и возвращает игровые объекты для подключения логики.

**Архитектура:** разбор документа отделён от создания игровых объектов. Описания типов отвечают за различия компонентов; общий построитель управляет порядком создания, индексом объектов и очисткой. Чтение файлов и подключение меню к игровому экрану остаются в вызывающем Lua-коде.

**Технологии:** Lua 5.2, LuaCs/MoonSharp, GUI Barotrauma; Busted, StyLua, Selene. JSON разбирается включённым в пакет декодером Lunajson 1.2.3 на чистом Lua.

**Спецификация:** [идеи и соглашения](../specs/2026-11-03-ui-schema-design.md), [пояснения и точные правила](../specs/2026-11-03-ui-schema-guide.md); утверждены 3 ноября 2026 года.

## Общие ограничения

- Имя `ui_schema`, версия `0.1.0`, каталог `Lua/limanchel/pkg/ui_schema/v0_1_0/`.
- Основной каталог чата остаётся исходным проектом. Продолжать в существующем worktree `../advance-storage-system-worktrees/ui-schema`, ветка `codex/ui-schema`; команды выполнять с явно указанным рабочим каталогом.
- Вход — строка JSON. Функций чтения файлов и публичного приёма Lua-таблиц схем в библиотеке нет.
- Документ содержит `schema_version = 1` и `components` с именованными заготовками. Штатное размещение игры, исходные GUI-объекты по `id`, независимые экземпляры и явный `dispose` обязательны.
- Создание UI — только на клиенте. Подключение модуля и разбор JSON не требуют GUI и не создают окна, подписки или новые регистрации типов игры.
- Ошибки — `limanchel.pkg.goerrors.v0_1_0.goerrors`; ожидаемый отказ возвращается как `nil, err`, нарушение Lua-контракта вызывает строковую ошибку.
- Для каждого собственного Lua-модуля создавать `.d.lua`. README, комментарии, диагностика и тестовые описания — на русском. Оригинал лицензии стороннего кода сохраняется без перевода.
- Архивный `ui_runtime`, `Lua/Autorun/main.lua` и меню хранилища не изменяются. Собственный C#-мост, язык выражений, редактор и механизм вёрстки не добавляются.

## На что обратить внимание при проверке

| Условие | Ожидаемое поведение | Где закрепляется |
| --- | --- | --- |
| Пустые `{}`, `[]`, `null`, `false` и нулевое значение | Формы различаются; ложь и ноль не теряются; `null` отклоняется | Задачи 2–3 |
| Явный `$nil` посреди параметров конструктора | Сохраняется отличие от пропущенного параметра, следующие аргументы не сдвигаются | Задачи 3 и 5 |
| Два экземпляра строки с одинаковыми `id` и повторное использование документа | Объекты разные, локальные ссылки правильные, документ не изменён | Задача 4 |
| Конструктор или запись свойства падает после частичного создания | Удалены созданные объекты и регистрации; чужие ресурсы сохранены; ошибка очистки не скрывает исходную | Задачи 4 и 7 |
| Команда выполнена, но игра ещё не нарисовала кадр либо открыта консоль | Отчёт не выдаёт преждевременный `ready`; снимок сопоставляется с запуском и шагом | Задачи 8–9 |

### Контракты между модулями

Это внутренние интерфейсы реализации, не дополнительный публичный API:

- `json_decoder.decode(text) -> value, err`; `json_decoder.kind(value) -> "object" | "array" | "null" | type(value)`. Декодер вызывается без стартовой позиции, с собственным маркером `null` и флагом длины массива. Служебный индекс `[0]` массивов наружу не выходит.
- `document.parse(text) -> document, err`; `document.get_schema(document, name) -> node, err`. Документ хранит только данные; они не меняются построением.
- `registry.new() -> registry`; методы `register_type`, `register_value_type`, `register_enum`, `get_type`, `get_value_type`, `get_enum` с параметрами имён и соответствующих описаний.
- `values.resolve(spec, context, path) -> value, err`. Успешное значение может быть `nil` или `false`: проверять наличие `err`, а не истинность результата. Контекст содержит ресурсы, текущие объекты по `id`, описания значений и доступ к нативным операциям.
- `native.new() -> backend`, не обращающийся к GUI до вызова операций. Методы `is_client()`, `get_type(name)`, `get_enum(name)`, `new_value(name, args)`, `new_rect(spec, parent)`, `read_member(object, path)`, `write_member(object, path, value)`, `detach(object)` работают с исходными объектами.
- `build.run(document, name, parent, context, registry, backend) -> view, err`. `view` предоставляет согласованные `root`, `by_id`, `get` и `dispose`.
- `types_basic.register(registry, backend)`, `types_controls.register(...)`, `types_special.register(...)` добавляют описания, не создавая GUI при регистрации.

Описание компонента содержит `rect_mode = "new" | "parent" | "none"`, функции `validate(constructor, path) -> true, err`, `create(params, rect_or_parent, context) -> object, err`, `child_parent(object, slot) -> parent, err`, `destroy(object) -> true, err`. Режим `new` просит построитель создать `rect`, `parent` передаёт внешний прямоугольник в конструктор, `none` оставляет размещение типу. `params` содержит `values`, `present` и `variant`: так явно переданный `nil` отличается от отсутствующего параметра. Контекст создания предоставляет `context.defer_cleanup(callback)` для очистки уже начатых действий при отказе до возврата объекта. После успешного возврата объекта временные callbacks этого вызова снимаются: за дальнейшую очистку, включая откат последующих узлов, отвечает его `destroy`. При отказе самого `create` выполняются временные callbacks; `destroy` для не возвращённого объекта не вызывается.

## Команды проверки

В PowerShell из worktree определить `$uiPkg = 'Lua/limanchel/pkg/ui_schema/v0_1_0'`. Для файла `<имя>_test.lua` использовать:

```powershell
wsl --exec env 'LUA_PATH=./Lua/?.lua;./Lua/?/init.lua;;' busted --lua=lua5.2 --pattern='_test%.lua$' "$uiPkg/<имя>_test.lua"
```

Переменная окружения вместо `--lpath` сохраняет тот же путь модулей и обходит наблюдавшееся раскрытие `;` при запуске Busted через WSL. Для всех тестов последний аргумент заменить на `Lua`.

После каждой задачи с изменением Lua: целевые тесты, `python tools/luafmt/luafmt.py`, `python tools/lualint/lualint.py $uiPkg`, затем `git diff --check`. Для задачи только с документацией достаточно проверки источников, ссылок и diff. Успех — ноль отказов/ошибок и код завершения 0. Перед коммитом добавлять только файлы своей задачи, включая определения и README. Формулировки коммитов ниже — рекомендуемые.
