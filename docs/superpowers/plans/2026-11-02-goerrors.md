# План реализации goerrors

> **Для агентов:** выполнять по задачам через `superpowers:executing-plans` либо `superpowers:subagent-driven-development`, согласно выбранному пользователем способу. Отмечать выполненные шаги флажками.

**Цель:** выпустить `goerrors` версии `0.1.0` для создания, оборачивания и поиска объектов ошибок.

**Архитектура:** один чистый Lua-модуль с четырьмя публичными функциями: `new`, `wrap`, `is`, `as`. Встроенные объекты используют локальные отдельные таблицы класса и метатаблицы; пользовательские ошибки подключаются по методам `error()` и необязательному `unwrap()`. Оба поиска используют общий внутренний обход дерева.

**Средства:** Lua 5.2, Busted/Luassert в WSL, LuaCATS, проектные `luafmt` и `lualint`; дополнительная проверка MoonSharp при доступном запуске игры.

**Спека:** [утверждённый дизайн](../specs/2026-11-02-goerrors-design.md). Прочитать его вместе с `AGENTS.md`, `docs/AGENTS.md`, соглашениями в `docs/development/` и навыком `.codex/skills/lua-style/SKILL.md` перед выполнением плана.

## Общие ограничения

- Начальная версия — `0.1.0`, путь — `Lua/limanchel/pkg/goerrors/v0_1_0/`, импорт — `limanchel.pkg.goerrors.v0_1_0.goerrors`.
- Только стандартные средства Lua 5.2; без зависимостей от игры, C#, сторонних пакетов и архивных контрактов.
- Ожидаемые сбои потребителей — `nil, err`; конструкторы пакета возвращают непосредственно объект ошибки. Нарушения контракта вызывают строковые `error()`/`assert()`.
- Публичные функции — только `new`, `wrap`, `is`, `as`; получение строки — `err:error()`. Форматирование контекста выполняется заранее через `string.format`.
- `unwrap()` возвращает плотный массив причин; у листа метод отсутствует либо возвращает пустой массив. `nil` вместо массива не допускается.
- Сопоставление объектов и классов — по ссылке, без `__eq`. Поиск класса поддерживает непосредственную метатаблицу и её собственный табличный `__index`; наследование и защищённые метатаблицы не поддерживаются.
- Порядок поиска — в глубину, текущий узел перед причинами, причины в порядке массива; первое совпадение завершает поиск.
- Циклы нарушают контракт, автоматическая диагностика не требуется. Повторение одного объекта в разных ветвях допустимо.
- Код, тесты, комментарии и документация — на русском. Архив, `Lua/Autorun/main.lua`, настройки инструментов и способы объявления классов проекта не меняются.

## Особое внимание при ревью

Каждый случай закрепляется тестами в указанной задаче.

1. Завершающий `nil` в varargs `wrap` не должен теряться при подсчёте причин — задача 1.
2. Разреженный массив пользовательского `unwrap` не должен молча обрываться при обходе — задача 2.
3. Пользовательский `__eq` не должен давать ложное совпадение объектов или классов — задача 2.
4. Наследуемое поле `__index` и функция `__index` не должны расширять сопоставление класса — задача 2.
5. Совпадение в текущем узле не должно вызывать его `unwrap`; найденная ветвь не должна приводить к посещению следующих — задача 2.

## Задача 2: поиск причины и пользовательского класса

**Файлы:** дополнить те же четыре файла пакета.

**Интерфейсы:**

- Вход: `goerrors.Error` и конструкторы задачи 1; `unwrap(self): goerrors.Error[]` у пользовательских обёрток.
- Выход: `goerrors.is(err: goerrors.Error|nil, target: goerrors.Error|nil): boolean`; `goerrors.as(err: goerrors.Error|nil, error_class: table): goerrors.Error|nil`. `as` возвращает исходный экземпляр; LuaCATS может уточнять его тип через generic без изменения runtime-контракта.

- [x] **1. Написать тесты порядка обхода, идентичности и сопоставления класса.** Включить следующие самостоятельные сценарии:

  | Сценарий | Проверки |
  | --- | --- |
  | Сам объект, глубокая и вторая ветви | `assert.is_true(goerrors.is(root, root))`; поиск исходного листа внутри `wrap("верх", wrap("ветвь", leaf), other)` успешен; отсутствующий объект и `new` с тем же текстом дают `false` |
  | Первое совпадение в глубину | Два объекта одного класса: первый глубоко в первой ветви, второй непосредственно во второй; `assert.is_true(rawequal(first, goerrors.as(root, ErrorClass)))`; подходящий корень имеет приоритет над причинами |
  | Оба способа класса | `setmetatable(instance, ErrorClass)` с `ErrorClass.__index = ErrorClass` и `setmetatable(instance, { __index = ErrorClass })` находятся через один и тот же `as(err, ErrorClass)` |
  | Идентичность при `__eq` | Разные объекты с общим `__eq`, возвращающим `true`, не совпадают в `is`; разные таблицы классов с таким же `__eq` не совпадают в `as` |
  | Без наследования и вычисляемого класса | Производный класс не находится по базовому; объект без метатаблицы не совпадает; функция `__index` и поле `__index`, доступное лишь через метатаблицу метатаблицы, не используются для сопоставления |
  | Пользовательские обёртки | Методы возвращают плотный массив причин, отсутствие `unwrap` и пустой массив обозначают листья; повторная ссылка на один лист в нескольких ветвях допустима |
  | Некорректный `unwrap` | `assert.has_error` при посещении узла, где `unwrap()` возвращает `nil`, строку, разреженный массив `{ [1] = leaf, [3] = other }` или массив с не-ошибкой; присутствующее поле `unwrap`, не являющееся функцией, включая `false`, также нарушает контракт |
  | Пустые значения и аргументы | `is(nil, nil)` — `true`; `is(nil, leaf)` и `is(leaf, nil)` — `false`; `as(nil, ErrorClass)` — `nil`; неверные непустые типы ошибок и нетабличный класс дают строковую ошибку использования |
