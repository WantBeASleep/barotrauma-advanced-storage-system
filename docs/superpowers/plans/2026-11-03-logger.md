# План реализации logger

> **Для исполнителя:** используй `superpowers:executing-plans` при самостоятельной реализации либо `superpowers:subagent-driven-development` при выборе реализации через субагентов. Выбор способа выполнения согласуется с пользователем перед реализацией. Шаги отмечаются через `- [ ]`.

**Цель:** создать пакет logger 0.1.0 с явными настройками, пятью уровнями, читаемыми именованными полями и производными экземплярами.

**Архитектура:** один Lua-модуль с таблицей публичного API, локальным классом экземпляра и приватными функциями проверки и форматирования. Настройки принадлежат экземпляру; функция вывода передаётся по ссылке, массивы префиксов копируются. Общий путь формирования записи проверяет порог до обращения к аргументам и вызывает `write` один раз после сборки строки.

**Стек:** Lua 5.2 / MoonSharp, Busted и Luassert в WSL, StyLua и Selene через проектные Python-утилиты.

**Спецификация:** [утверждённый дизайн](../specs/2026-11-03-logger-design.md). Перед кодом прочитать её, `docs/development/{structure,packages,coding,tooling}.md`, навык `.codex/skills/lua-style/SKILL.md` и его справочники `references/{testing,luacats}.md`.

## Общие ограничения

- Версия `0.1.0`, каталог `Lua/limanchel/pkg/logger/v0_1_0/`; импорт `limanchel.pkg.logger.v0_1_0.logger`.
- Обязательны `level`, `prefixes`, `write`; значений по умолчанию нет. Для стандартного вывода передаётся `write = print`.
- Уровни `trace < debug < info < warning < error`, методы в `snake_case`, `fields` имеет только строковые ключи.
- Формат `[ASS][storage][filters][INFO] Предмет отклонён {item_id = 42; reason = blacklist}`; блок `{}` без полей отсутствует.
- Lua 5.2, включая MoonSharp/LuaCs; клиент и сервер. Внешних пакетов, игрового API и C#-моста не требуется.
- Исходники, README, комментарии, аннотации и названия сценариев тестов — на русском. Новые игровые потребители и изменения Autorun не входят в задачу.
- Продолжать в существующем worktree `../advance-storage-system-worktrees/lua-logger`, ветка `codex/lua-logger`. Основной каталог чата сохранять в исходном проекте; явно задавать рабочий каталог команд.

## Файлы и команды

Создать в `Lua/limanchel/pkg/logger/v0_1_0/` четыре файла: `logger.lua` — вся реализация; `logger.d.lua` — публичные типы и методы; `logger_test.lua` — проверки контракта; `README.md` — версия, источник, среда, контракт и примеры. Дополнительные внутренние модули не нужны. Типы: `logger.Level`, `logger.Options`, `logger.Logger`, `logger.Lib`; таблица полей описывается как `table<string, any>`.

Во всех задачах команда целевых тестов из корня worktree:

```powershell
wsl --exec lua5.2 /usr/bin/busted --pattern='_test%.lua$' --lpath='./Lua/?.lua;./Lua/?/init.lua' Lua/limanchel/pkg/logger/v0_1_0/logger_test.lua
```

Ниже она обозначается как «целевые тесты». Использовать явные `require("busted")`, `require("luassert")` и локальные `describe`/`it`, как в тестах goerrors. Каждый тест создаёт собственную функцию `write`, которая сохраняет полученные строки и проверяет `select("#", ...) == 1`; исключения проверяются через `pcall` без привязки к номеру строки.

## Риски для проверки

1. Разреженный массив префиксов и лишние ключи не должны молча теряться: задача 1 отклоняет их как нарушение плотного массива.
2. Значения `false` и `0`, пустой ключ и пустое сообщение должны сохраняться: задачи 1–2 проверяют точный текст.
3. Подавленная запись с неверными аргументами и опасным `__tostring` не должна проверять или вычислять их: задача 1.
4. CR/LF в каждом текстовом компоненте не должны создавать физические переносы; обычные разделители и обратная косая черта сохраняются: задача 2.
5. Замыкающий `nil` в `with_prefix` и изменение исходных настроек не должны теряться или менять уже созданный экземпляр: задачи 1 и 3.

Решения при исполнении:

- Команды запускают Busted напрямую через `lua5.2 /usr/bin/busted`: установленный Busted с `--lua` повторно запускает shell и теряет экранирование `;` в `lpath`. Выбор интерпретатора и состав проверок сохранены.
- Краткие задания извлекались через PowerShell: скрипт навыка распознаёт только английские заголовки `Task`, а план написан по-русски. Границы сверены с исходным планом.
- Подмены глобальных функций восстанавливаются через экспортируемый `after_each`: `finally` доступен только внутри окружения теста, но не через `require("busted")`. Это разрешённый проектным справочником способ очистки.
