# План реализации filestore

> **Для исполнителя:** обязательный навык — `superpowers:executing-plans` при самостоятельной реализации либо `superpowers:subagent-driven-development` при выбранной пользователем работе через субагентов. Выполнять задачи по порядку; шаги отмечены флажками.

**Цель:** выпустить лёгкий Lua-пакет `filestore` для локального сохранения и загрузки текста по относительным ключам.

**Архитектура:** обычные функции модуля используют `Game.SaveFolder` и встроенный `File` LuaCs. Запись идёт в соседний временный файл с последующей заменой назначения; ошибки ввода-вывода совместимы с `goerrors`.

**Технологии:** Lua 5.2/MoonSharp, LuaCs 1.0.117, Busted/Luassert через WSL, проектные StyLua/Selene.

**Дизайн:** [утверждённый контракт](../specs/2026-11-04-filestore-design.md). Перед реализацией прочитать его и относящиеся проектные соглашения из `docs/development/README.md`, `docs/AGENTS.md`, `.codex/skills/lua-style/SKILL.md` и его справочники LuaCATS/тестов.

## Общие ограничения

- Пакет `filestore` версии `0.1.0`: `Lua/limanchel/pkg/filestore/v0_1_0/`.
- Зависимость — `limanchel.pkg.goerrors.v0_1_0.goerrors`.
- Единственный корень — `<Game.SaveFolder>/ModFiles/`. Значение `Game.SaveFolder` берётся при операции.
- Встроенные `Game` и `File`, без собственного C#-моста; клиент и сервер работают локально независимо.
- Только текст; без сериализации, сети, кеша, удаления, перечисления файлов и настройки корня в публичном API.
- `save(key, text)` возвращает `true` либо `nil, err`; `load(key)` — строку либо `nil, err`.
- Суффикс `.filestore-tmp` зарезервирован. Одновременная запись нескольких процессов в один ключ не поддерживается первой версией.
- Вся документация, комментарии, аннотации и сообщения об ошибках — на русском языке.
- Изоляцию перед исполнением создать через обычный `git worktree add -b codex/filestore ../advance-storage-system-worktrees/filestore`; основной каталог чата оставить исходным. Все команды реализации выполнять с явно указанным рабочим каталогом worktree. Перед созданием проверить ветки, существующие worktree и отсутствие несохранённых изменений.

## Что особенно проверить

1. Смена `Game.SaveFolder` между вызовами: следующий вызов использует новый корень; покрывает задача 1.
2. Каталог вместо файла, ошибка проверки существования и исчезновение файла перед чтением: ожидаемый сбой не маскируется успешной загрузкой; покрывает задача 1.
3. Служебный суффикс с другим регистром в промежуточном сегменте, устройства Windows с расширением и завершающие точки/пробелы: отказ до дисковых операций; покрывает задача 1.
4. Частично записанный временный файл и неудачная очистка: прежний целевой файл остаётся, исходная ошибка сохраняется вместе с ошибкой очистки; покрывает задача 2.
5. Существующий файл на месте родительского каталога и ошибка замены назначения: `nil, err`, без отдельного удаления назначения; покрывает задача 2.

## Файлы и ответственность

Создать только `Lua/limanchel/pkg/filestore/v0_1_0/filestore.lua`, `filestore.d.lua`, `filestore_test.lua` и `README.md`. Реализация помещается в один модуль: проверка ключа, вычисление пути, преобразование платформенного сбоя в ошибку, чтение и сохранение. Тестовые подмены локальны тестовому файлу. `Lua/Autorun/main.lua`, архив и другие потребители не изменяются.

## Задача 2: сохранение и проверка полного пакета

**Файлы:** дополнить те же четыре файла. Новые зависимости и файлы не нужны.

**Интерфейсы:** использует проверку ключа/пути и ошибки задачи 1; предоставляет `filestore.save(key: string, text: string): true|nil, goerrors.Error?`. Потребляет `File.CreateDirectory(parent)`, `File.Write(temporary, text)`, `File.Move(temporary, target)` и `File.Delete(temporary)`.

- [x] **1. Написать тесты сохранения.** Подмена файловой системы должна воспроизводить запись/перемещение/удаление, различать файлы и каталоги, а также позволять отказ после частичной записи. Основные проверки:

  ```lua
  -- «сохраняет текст с созданием вложенных каталогов»
  assert.is_true(filestore.save("ass/storagecfgs/cfg1.json", "Привет\r\nмир\n"))
  assert.are.equal("Привет\r\nмир\n", files["saves/ModFiles/ass/storagecfgs/cfg1.json"])
  assert.is_nil(files["saves/ModFiles/ass/storagecfgs/cfg1.json.filestore-tmp"])
  -- «сбой записи временного файла сохраняет прежний целевой»
  -- Подготовить прежний файл и отказ Write после записи части текста.
  local ok, err = filestore.save("settings.json", "новое")
  assert.is_nil(ok)
  assert.is_true(goerrors.is(err, filestore.errors.write_failed))
  assert.are.equal("старое", files["saves/ModFiles/settings.json"])
  ```

  Отдельно проверить пустую строку, обычную перезапись, длинный текст без усечения, смену корня между сохранениями, отсутствие преобразования таблицы/числа в текст, все правила ключей до дисковых обращений, отказ `CreateDirectory` и `false` от него, родитель-файл, отказ `Move`, успешную/неуспешную очистку после отказа `Write` и `Move`. Для двойного отказа проверить в дереве причин и описании обе ошибки. Журнал подтверждает запись только во временный файл и отсутствие `Delete(target)`.

Несвязанные файлы и соседние ключи остаются неизменными. После валидации ключа и получения пути очистка касается только его временного файла; не удалять какие-либо файлы при ошибке аргументов.

## Результат выполнения

Реализованы обе задачи. Итоговое независимое ревью выявило обращения к CONIN$/CONOUT$, изменение Linux-корня, обход запрета временного файла через короткое имя NTFS и пропуск C1. Для исправлений сначала получены 21 отказ регрессионных тестов, затем 227/227 целевых и 456/456 общих тестов прошли; форматирование и линт выполнены. На настоящей установленной MoonSharp отдельно прошли 14 проверок отказа до I/O и допустимый Unicode-ключ.

Дополнение исполнителя к правилам ключей: часть сегмента до первой точки не может заканчиваться на `~` и цифры. Это перекрывает автоматически создаваемые 8.3-псевдонимы временных файлов и также исключает обычные имена такой формы; правило отражено в README.

Проверка доступности игровой среды выполнена: клиент и сервер не запущены. Полный игровой startup/restart не выполнялся; его нельзя считать подтверждённым Busted или отдельным MoonSharp-host. Инструкция включена в README. Независимое ревью и его исправления завершены. По поручению пользователя ветка `codex/filestore` влита в `master`; после merge повторно прошли 456 тестов и линт пакета. Worktree и слитая ветка удалены после проверки чистоты и слитых коммитов, без `--force`.
