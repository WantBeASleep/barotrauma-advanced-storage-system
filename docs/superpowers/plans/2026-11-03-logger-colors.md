# План реализации цветов logger

> **Для исполнителя:** `superpowers:executing-plans`, самостоятельная реализация в этом чате с отдельным ревью всей ветки, как ранее выбрал пользователь. Шаги отмечаются через `- [ ]`.

**Цель:** окрасить всю запись цветом её уровня через `write(line, color)` с игровым `Color`.

**Архитектура:** внутренняя таблица пяти игровых цветов создаётся при загрузке модуля. После проверки порога и формирования прежней строки логгер передаёт её и выбранный цвет в единственный вызов `write`; производные экземпляры используют ту же палитру.

**Стек:** Lua 5.2 / LuaCs, `Microsoft.Xna.Framework.Color`, Busted/Luassert, StyLua/Selene.

**Спецификация:** [цвета logger](../specs/2026-11-03-logger-colors-design.md), дополняет [исходный контракт](../specs/2026-11-03-logger-design.md).

## Общие ограничения

- Менять существующую `0.1.0` в `Lua/limanchel/pkg/logger/v0_1_0/`: пользователь подтвердил невыпущенную разработку без клиентов и разрешил исключение из повышения версии.
- `write(line, color)` принимает ровно два аргумента; `color` имеет тип `Microsoft.Xna.Framework.Color`. Настройки `level`, `prefixes`, `write` обязательны; новой настройки палитры нет.
- Палитра: `trace = Color.Beige`, `debug = Color.LimeGreen`, `info = Color.SkyBlue`, `warning = Color.Orange`, `error = Color.Red`.
- `Color` должен быть доступен при загрузке. Никаких RGB-таблиц, ANSI, бесцветного fallback и нового C#-кода в реализации.
- Сохраняются текст, `{}` для полей, сортировка, `tostring`/`__pairs`, обработка ошибок и подавление до обращения к аргументам.
- Продолжать в worktree `../advance-storage-system-worktrees/lua-logger`, ветка `codex/lua-logger`. Документация и комментарии по-русски; правила проекта и `lua-style` обязательны.

## Риски для ревью

1. Перепутанный оттенок `info`: проверяется именно игровой `SkyBlue`, не `Blue`/`CornflowerBlue`.
2. Случайная потеря цвета или дополнительный вывод: во всех обычных сценариях функция-сборщик проверяет два аргумента и одну готовую строку за вызов.
3. Производный логгер окрашивает сообщение по порогу вместо собственного уровня: проверяются разные разрешённые уровни у ребёнка и родителя.
4. Подмена `Color` или очистка `package.loaded` в тестах влияет на соседние тесты: загрузочный помощник восстанавливает глобальное значение даже при сбое; отдельные подмены очищаются через `after_each`.
5. README/типы продолжают обещать чистый Lua и прямой `print`: обновляются вместе с кодом, проверяются при ревью.
