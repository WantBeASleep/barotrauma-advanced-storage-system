# logger: цвета уровней

Статус: проект дополнения для согласования. Изменяет [исходную спецификацию](2026-11-03-logger-design.md).

## Назначение

Вся запись, включая префиксы, уровень, сообщение и поля, выводится цветом своего уровня. Палитра зашита в пакет; потребитель выбирает уровень сообщения и не настраивает цвета.

## Согласованные решения

- Логгер зависит от LuaCs и передаёт игровой объект `Microsoft.Xna.Framework.Color`.
- Контракт функции вывода: `write(line, color)`, ровно два аргумента и один вызов на разрешённую запись. Функция окрашивает всю полученную строку.
- Настройки `level`, `prefixes`, `write` остаются обязательными. Настройки палитры и переключателя цветного режима нет.
- По выбранному пользователем варианту 3 текущая `0.1.0` считается невыпущенной и без клиентов; разрешено изменить её контракт без повышения версии. Каталог и имя импорта сохраняются.

## Рассмотренные подходы

| Подход | Свойства | Решение |
| --- | --- | --- |
| Палитра на стороне `write` или в настройке `colors` | Позволяет потребителю выбирать цвета | Отклонён: палитра должна быть внутренней константой |
| Внутренняя RGB-палитра, `write` получает Lua-таблицу | Сохраняет независимость от игры, требует преобразования в игровой цвет | Отклонён: зависимость от LuaCs допустима и нужна |
| Внутренняя палитра игровых `Color`, `write(line, color)` | Цвет сразу готов для игровой консоли; пакет требует LuaCs | Выбран пользователем |

## Палитра

Конкретные оттенки ниже предложены исполнителем: зелёный и синий выбраны светлее стандартных `Green` и `Blue` для тёмного фона консоли.

| Уровень | Цвет LuaCs | RGB |
| --- | --- | --- |
| `trace` | `Color.Beige` | `245, 245, 220` |
| `debug` | `Color.LimeGreen` | `50, 205, 50` |
| `info` | `Color.CornflowerBlue` | `100, 149, 237` |
| `warning` | `Color.Orange` | `255, 165, 0` |
| `error` | `Color.Red` | `255, 0, 0` |

Все цвета непрозрачные, альфа `255`. Публичное имя уровня и метода остаётся `warning`; алиас `warn` не добавляется.

Глобальный `Color` доступен через [общую библиотеку LuaCs](https://github.com/evilfactory/LuaCsForBarotrauma/blob/master/Barotrauma/BarotraumaShared/LocalMods/LuaCsForBarotrauma/Lua/DefaultLib/LibShared.lua). Имена цветов и значения компонентов заданы в [справочнике MonoGame](https://docs.monogame.net/api/Microsoft.Xna.Framework.Color.html).

## Выполнение и совместимость

Палитра создаётся из игровых цветов при загрузке модуля. `Color` должен быть доступен до `require`; без LuaCs пакет не обещает работу и не подменяет цвета таблицами или строками. Загрузка не выводит сообщения и не меняет глобальные значения.

Формат строки с аргументами в `{}`, порядок полей, `tostring`, обработка `__pairs` и поведение ошибок сохраняются. ANSI-последовательности и цветовая разметка в строку не добавляются. Подавленный вызов не форматирует аргументы и не вызывает `write`.

`with_prefix` наследует тот же порог и ту же функцию вывода; цвет каждого сообщения выбирается по его собственному уровню из общей внутренней палитры. Цвет не становится настройкой или изменяемым состоянием экземпляра. Пользовательский `write` не должен менять полученный объект цвета.

Прежний `write(line)` заменяется на `write(line, color)`. Передача `print` напрямую больше не соответствует назначению функции: она выводит аргументы как текст и не применяет игровой цвет. README и определения API обновляются на новый контракт. Поставляемая функция вывода и её интеграция с конкретной консолью остаются ответственностью потребителя; новых игровых потребителей пакет не создаёт.

## Проверки и границы

Проверить точный игровой цвет каждого уровня, два аргумента и единственный вызов `write`, сохранение текста строки, наследование в производных логгерах и отсутствие вывода подавленных сообщений. Существующие проверки должны продолжать покрывать весь контракт форматирования и ошибок.

В тестах под Lua 5.2 подменять только внешний `Color` контролируемыми значениями с восстановлением окружения. Не добавлять тестовые обходы в реализацию. Проверку через настоящий LuaCs отличать от тестов с подменой; без запуска среды не заявлять визуальную проверку игры. После изменений обязательны полный набор Lua-тестов, проектное форматирование и линт.

Публичные методы, исходники пакета и документация остаются в прежнем каталоге. Новые зависимости-пакеты, C#-код, настройка палитры, бесцветный режим и изменение формата текста в задачу не входят.
