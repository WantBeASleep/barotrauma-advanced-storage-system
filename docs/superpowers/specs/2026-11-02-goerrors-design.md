# goerrors: объекты и деревья ошибок

Статус: проект на согласование. Реализация не начата.

## Назначение

Единый переиспользуемый Lua-пакет для ожидаемых ошибок будущих модулей мода. При сбое модуль возвращает `nil, err`; вызывающий код может добавить контекст, проверить причину, извлечь пользовательскую ошибку и получить описание для человека.

Ошибки передаются объектами, а не произвольными строками и таблицами. Преобразование в строку означает получение описания; обратное восстановление объекта, JSON и передача по сети в задачу не входят.

## Согласованные решения

- Ожидаемые ошибки возвращаются через `nil, err`. Объекты не передаются через `error()`; по указанному пользователем ограничению MoonSharp это не поддерживается.
- Ошибка определяется контрактом методов, без регистрации и обязательного базового класса.
- Простые ошибки создаёт пакет; пользовательские классы реализуют тот же контракт.
- Обёртка сохраняет ссылки на причины, в том числе несколько причин, образующих дерево.
- `is` сравнивает идентичность объектов, а не сообщения.
- `as` принимает таблицу класса и возвращает найденный объект. Класс непосредственно служит метатаблицей экземпляра; наследование не учитывается.
- Полное воспроизведение пакетов Go не требуется.

## Рассмотренные подходы

| Подход | Преимущества | Ограничения |
| --- | --- | --- |
| Контракт по методам | Пользовательские классы независимы от реализации пакета; регистрация не нужна | Автор класса соблюдает контракт описания и причин |
| Обязательный базовый класс | Общая реализация методов и единая иерархия | Связывает все ошибки с классом пакета |

Выбран первый подход: будущим пакетам достаточно реализовать небольшой контракт.

Архивный `archive/lua/lib/errors` остаётся источником контекста: он поддерживает обёртки и несколько причин, но ограничивает ошибки собственной метатаблицей и ищет по тексту. Перенос его API и миграция архивных потребителей не входят в задачу.

## Предлагаемый контракт

Следующие подробности предложены при подготовке дизайна и требуют согласования вместе с документом.

### Объект ошибки

Ошибка — Lua-таблица с доступным методом `err:error()`, возвращающим строку. Метод может находиться в классе через `__index`. Описание полностью определяет автор ошибки; пакет не добавляет к нему причины автоматически.

Необязательный `err:unwrap()` возвращает плотный массив непосредственных причин, начиная с индекса 1. Для листа метод отсутствует либо возвращает пустой массив. `nil` вместо массива не допускается. Каждый элемент — объект с тем же контрактом; в том числе для одной причины используется массив.

Класс для `as` — таблица, непосредственно переданная в `setmetatable(instance, ErrorClass)`. Поэтому для ошибок используется `ErrorClass.__index = ErrorClass`: это согласованное отступление от примера с отдельной `Class_mt` в `lua-style`. Защищённые метатаблицы, скрывающие класс через `__metatable`, не поддерживаются.

Методы описания и получения причин не должны менять дерево. Циклы нарушают контракт; их диагностика и восстановление не входят в первую версию. Один объект может встречаться в нескольких ветвях. Пакет не копирует пользовательские ошибки и не меняет их поля.

### Публичные функции

Имена записываются в `snake_case` по соглашениям проекта; алиасов `New`, `Is`, `As` нет.

| Вызов | Результат |
| --- | --- |
| `goerrors.new(message)` | Новый объект простой ошибки; одинаковые сообщения не делают разные объекты идентичными |
| `goerrors.wrap(message, err, ...)` | Новый объект с контекстом и одной или несколькими причинами в порядке аргументов |
| `goerrors.is(err, target)` | `true`, если сам `err` или одна из причин — тот же объект, что `target`; иначе `false` |
| `goerrors.as(err, ErrorClass)` | Первый объект с указанной непосредственной метатаблицей либо `nil` |
| `goerrors.to_string(err)` | Строка, полученная вызовом `err:error()`, в том числе для пользовательской ошибки |

`message` — обязательная строка; пустая строка допустима. `new` и `wrap` возвращают непосредственно ошибку, поскольку сами являются конструкторами. Форматирование аргументов выполняет обычный `string.format` до вызова `wrap`; отдельного `errorf` и разбора `%w` в первой версии нет.

`wrap` требует хотя бы одну причину и не пропускает `nil`, в том числе в конце списка аргументов. Он создаёт собственный массив причин, сохраняя сами объекты по ссылке. Метод `unwrap` встроенной обёртки возвращает копию массива: изменение возвращённого списка не меняет состав обёртки. Встроенные ошибки и обёртки предоставляют `__tostring`, делегирующий `error()`; для пользовательских ошибок `__tostring` необязателен.

`is` использует сравнение ссылок без вызова `__eq`; `as` так же сравнивает метатаблицу с классом. Пользовательских методов переопределения поиска нет. `as` не вызывает конструктор, не преобразует объект и не требует, чтобы класс сам был объектом ошибки.

Оба поиска обходят дерево в глубину: сначала текущий объект, затем целиком каждую ветвь по порядку причин. Поиск останавливается при первом совпадении. Сообщения ошибок при поиске не вычисляются. Скорость определяется числом посещённых узлов; индексирование и кеширование не нужны.

Для поиска `nil` означает отсутствие ошибки: `is(nil, nil)` возвращает `true`, `is(nil, target)` при `target ~= nil` и `is(err, nil)` при `err ~= nil` возвращают `false`, `as(nil, ErrorClass)` возвращает `nil`. Для `new`, `wrap` и `to_string` это не разрешает `nil` вместо обязательного аргумента.

Неверные типы аргументов и обнаруженное нарушение контракта — ошибки использования API. Они вызывают обычный `error()`/`assert()` со строковым сообщением. Они не превращаются в ожидаемую ошибку `goerrors`. Ошибки выполнения пользовательских методов не перехватываются и не маскируются. Полная предварительная проверка всех ветвей не требуется: результат поиска может быть получен до посещения других ветвей.

### Текст встроенных ошибок

- Простая ошибка возвращает `message` без изменений.
- Обёртка одной причины возвращает `message: причина`.
- Обёртка нескольких причин возвращает `message: [причина 1; причина 2]`.

Для каждой причины вызывается её `error()`. Строка пользовательской ошибки включается без разбора и экранирования. Формат предназначен для человека; машинный разбор строки не является контрактом. При пустом контексте разделитель сохраняется.

**Пример:** создание, обёртка и поиск причины.

```lua
local goerrors = require("limanchel.pkg.goerrors.v0_1_0.goerrors")

local err_storage_full = goerrors.new("хранилище заполнено")
local err = goerrors.wrap("не удалось переместить предмет", err_storage_full)

assert(goerrors.is(err, err_storage_full))
assert(not goerrors.is(err, goerrors.new("хранилище заполнено")))
print(goerrors.to_string(err))
-- не удалось переместить предмет: хранилище заполнено
```

**Пример:** пользовательский класс без базового класса пакета.

```lua
local StorageError = {}
StorageError.__index = StorageError

function StorageError:error()
    return string.format("недоступно хранилище %s", self.storage_id)
end

local original = setmetatable({ storage_id = 42 }, StorageError)
local err = goerrors.wrap("загрузка настроек", original)
local found = goerrors.as(err, StorageError)

assert(rawequal(found, original))
print(found.storage_id)
```

## Поставка и границы

Предлагаемая начальная версия — `0.1.0`, путь — `Lua/limanchel/pkg/goerrors/v0_1_0/`. Состав: `goerrors.lua`, `goerrors.d.lua`, `goerrors_test.lua` и русскоязычный `README.md`. Источник исходников — этот репозиторий. Пакет использует только стандартные средства Lua 5.2, без зависимостей от игры, C# и сторонних пакетов; пригоден для клиента и сервера.

Публичные классы встроенных ошибок не экспортируются: для простых причин предназначен `is`, для собственных классов — `as`. Внутреннее устройство таблиц встроенных ошибок не является API; вызывающий код их не изменяет.

Не входят: выбрасывание объектов через `error`, traceback, логирование, наследование, сравнение по тексту или кодам, регистрация типов, автоматическое превращение произвольных значений в ошибки и обновление архивных модулей.

При реализации нужно согласованно обновить раздел об ожидаемых ошибках в `lua-style`: для новых пакетов использовать `nil, err`, где `err` соблюдает контракт `goerrors`, вместо обязательной строки. Нарушения API по-прежнему сообщаются строковым `error()`/`assert()`. Другие правила навыка и архивный код не меняются.

## Проверка

Тесты должны проверить идентичность при одинаковых сообщениях и пользовательском `__eq`; поиск в корне, глубоких и нескольких ветвях; выбор первого совпадения; точный класс без наследования; пользовательские листья и обёртки; сохранение полей и ссылок; копирование массива причин; текст простых и составных ошибок; правила `nil` и неверных аргументов. Отдельная проверка подтверждает, что поиск не вызывает `error()` объекта и не посещает ветви после совпадения.

Проверки реализации: Busted под Lua 5.2, затем форматирование и линт по `docs/development/tooling.md`. Совместимость с MoonSharp дополнительно проверяется коротким запуском сценариев создания, обёртки, поиска и преобразования в строку в установленной игре, если такой запуск доступен. Проверка обычным Lua не считается проверкой MoonSharp.

Разработчик выбирает внутренние вспомогательные функции и детали проверок аргументов; они не должны менять описанный контракт. Тексты диагностик неверного использования не фиксируются, но должны быть на русском и указывать нарушенное требование.
