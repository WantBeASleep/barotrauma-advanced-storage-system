# filestore: хранение текстовых файлов

Статус: утверждён пользователем 4 ноября 2026 года, включая уточнения контракта и границы первой версии.

## Назначение и границы

Общий лёгкий пакет сохраняет готовый текст по относительному ключу и загружает его после перезапуска игры. Ключ соответствует обычному пути с директориями; файл можно открыть через проводник. Формат содержимого, значения по умолчанию и момент сохранения определяет вызывающий код.

Первая версия работает только с текстом. Другие форматы потребуют отдельного пересмотра пакета и API. В пакет не входят JSON/XML-сериализация, настройки конкретного мода, сеть, автосохранение, кеш, резервные копии, удаление и перечисление файлов.

Клиент и сервер выполняют операции локально, без обмена файлами. Пакет не добавляет разделение по стороне выполнения: процессы с одинаковым корнем и ключом обращаются к одному физическому файлу. Одновременная запись нескольких процессов в один ключ не поддерживается первой версией.

## Рассмотренные подходы

1. Прямая запись через LuaCs `File.Write`: меньше кода, но ошибка перезаписи может повредить прежний файл.
2. Запись временного файла и замена через `File.Move`: небольшой дополнительный шаг сохраняет прежний файл при сбое записи временного. Пользователь выбрал этот вариант.

Собственный C# не нужен: требуемые операции уже предоставляет LuaCs. Архивный C#-сервис не переносим.

## Размещение и зависимости

- Пакет `filestore` версии `0.1.0`: `Lua/limanchel/pkg/filestore/v0_1_0/`.
- Публичная точка входа — `filestore.lua`; рядом `filestore.d.lua`, `filestore_test.lua` и README на русском языке.
- Зависимость — `limanchel.pkg.goerrors.v0_1_0.goerrors`.
- Среда — Lua 5.2 через LuaCs/MoonSharp, клиент и сервер. Используем встроенные `Game.SaveFolder` и `File`, без собственного C#-моста.
- Подключение модуля не создаёт каталоги, не читает и не записывает файлы. Конструктор и настройка корня не нужны.

## Корень и ключи

Единственный корень — `<Game.SaveFolder>/ModFiles/`. Значение `Game.SaveFolder` берётся при операции; путь не привязан к компьютеру или папке мода. При изменении настройки пути сохранений последующие операции используют новый корень; автоматического переноса старых файлов нет.

**Пример:** ключ `ass/storagecfgs/cfg1.json` соответствует `<Game.SaveFolder>/ModFiles/ass/storagecfgs/cfg1.json`. Первые сегменты выбирает вызывающий код; пакет не знает namespace или имени мода.

Правила ключа:

- Непустая строка с разделителем `/`, заканчивающаяся именем файла.
- Запрещены абсолютные пути, обратный слеш, пустые сегменты, `.` и `..`.
- Для одинаковой применимости на Windows и Linux запрещены управляющие символы, `< > : " | ? *`, завершающие сегмент точка/пробел и зарезервированные Windows-имена устройств, в том числе с расширением.
- Суффикс `.filestore-tmp` зарезервирован: ни один сегмент ключа не может заканчиваться им без учёта регистра.
- Ключ не нормализуется молча и не меняет регистр. Регистр файловых имён зависит от ОС; вызывающий код должен использовать одно написание.

Это ограничение адресации пакета, а не защита от изменений файловой системы извне. Символические ссылки, junction и подмена каталогов другим процессом не входят в гарантии первой версии.

## API и ошибки

| Вызов | Успех | Ожидаемый сбой |
| --- | --- | --- |
| `filestore.save(key, text)` | `true` | `nil, err` |
| `filestore.load(key)` | Строка, включая пустую | `nil, err` |

`save` полностью заменяет содержимое существующего файла. Родительские каталоги создаются автоматически при сохранении. `load` ничего не создаёт и при каждом вызове читает файл с диска, поэтому видит ручные изменения.

Текст передаётся строкой без автоматического преобразования значений. Запись использует UTF-8 без добавления BOM; чтение следует поведению текстового API LuaCs/.NET. Пустой текст допустим; переводы строк сохраняются. Двоичные данные и некорректный UTF-8 не входят в контракт.

Стабильные причины — объекты `filestore.errors.not_found`, `filestore.errors.read_failed` и `filestore.errors.write_failed`. Ошибки совместимы с `goerrors`; контекст содержит ключ, стадию операции и доступное описание платформенного сбоя. Отсутствующий при проверке файл возвращает `not_found`; исчезновение между проверкой и чтением может дать `read_failed`.

Неверный тип аргумента или недопустимый ключ — неправильное использование API, вызывающее строковый `assert`/`error` до обращения к диску. Отказы ввода-вывода возвращаются через `nil, err`. Пакет не пишет в лог и не выбирает запасной каталог.

## Сохранение через временный файл

Для целевого пути временный файл имеет имя `<целевой путь>.filestore-tmp` и находится в том же каталоге.

1. Проверить аргументы и получить путь внутри корня.
2. Создать родительские каталоги через `File.CreateDirectory`.
3. Записать весь текст во временный файл через `File.Write`.
4. Заменить целевой файл вызовом `File.Move(temporary, target)`. В проверенной версии LuaCs он использует `File.Move` с перезаписью назначения.
5. Вернуть `true` только после успешной замены.

До успешной записи временного файла целевой не изменяется. При ошибке пакет пробует удалить временный файл; сбой удаления добавляется в причины возвращаемой ошибки, сохраняя исходный сбой. Каталоги после ошибки не удаляются.

Оставшийся после аварийного завершения временный файл игнорируется при загрузке и перезаписывается следующей попыткой сохранения того же ключа. Его нельзя загружать как клиентский ключ. Глобальная уборка временных файлов и восстановление из них не выполняются.

Пакет не обещает транзакции, межпроцессные блокировки, сохранность при отключении питания или восстановление после ошибки самой замены. Прежний файл не удаляется отдельной операцией перед `Move`.

## Проверка и решения при реализации

Автотесты под Lua 5.2/Busted проверяют публичное поведение через подменённые `File` и `Game`: сохранение/чтение, вложенные каталоги, пустой и русский текст, ручные изменения, недопустимые ключи, отсутствие файла, ошибки создания/записи/замены/очистки, сохранение прежнего файла при сбое записи временного, повторную запись после оставшегося временного файла. Проверить, что `require` не обращается к диску и `load` не читает временный файл.

Изменённый Lua проходит проектные форматирование и линт. Отдельная проверка в игре должна подтвердить доступность `File.CreateDirectory`/`File.Move`, UTF-8 и загрузку после перезапуска; подмены API этого не подтверждают. Если игровую проверку нельзя выполнить, это явно указывается в результате.

Исполнитель выбирает внутреннее разбиение функций и деталей тестовых подмен. Не добавляет публичные операции или настройки без необходимости. Существенное расхождение установленной LuaCs с проверенными исходниками требует пересмотра технического решения.
