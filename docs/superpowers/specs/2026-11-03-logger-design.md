# logger: структурное логирование в консоль

Статус: утверждено пользователем 2026-11-03. Реализация не начата; [план реализации](../plans/2026-11-03-logger.md).

## Назначение и границы

Переиспользуемый Lua-пакет собирает читаемые сообщения с уровнем, цепочкой префиксов и именованными полями. Настроенный экземпляр передаётся потребителям как зависимость; каждый компонент может получить производный экземпляр со своими префиксами.

В первую версию входят только форматирование и синхронный вывод через функцию `write(line)`. Файлы, сеть, JSON, время, цвета, буферизация, рекурсивное раскрытие объектов и изменение настроек существующего экземпляра не входят в задачу. Подключение логирования к игровым фичам также вне этой задачи.

## Согласовано в обсуждении

- Уровни: `trace`, `debug`, `info`, `warning`, `error`.
- Минимальный уровень задаётся при создании экземпляра.
- Значения полей преобразуются штатным `tostring`: при наличии используется `__tostring`, иначе стандартное представление Lua. Отдельный метод объекта `tostring()` не вызывается.
- Явный вывод именованного поля со значением `nil` не требуется.
- Все настройки задаются явно при создании: `level`, `prefixes`, `write`. Значений по умолчанию нет; для стандартного вывода передаётся `write = print`.
- Производный экземпляр наследует настройки и дополняет цепочку префиксов, сохраняя исходный экземпляр.
- Блок именованных полей заключён в `{}`, префиксы и уровень — в `[]`.

## Рассмотренные подходы

| Подход | Преимущества | Ограничения |
| --- | --- | --- |
| Прямой вызов `print` внутри пакета | Минимум настроек, готовый вывод в консоль | Для перехвата вывода требуется подмена глобального `print` |
| Обязательный `write(line)` в настройках | Явная зависимость вывода, удобные проверки, независимость от игрового API | Функцию вывода нужно передавать при создании |

Пользователь выбрал второй подход. Применение `print` для вывода в консоль описано в [руководстве LuaCs](https://evilfactory.github.io/LuaCsForBarotrauma/lua-docs/manual/getting-started/).

## Утверждённый контракт

Сигнатуры, сортировка, точный формат и обработка некорректных вызовов утверждены вместе с документом.

### Создание

`logger.new(options)` возвращает новый настроенный экземпляр. Таблица настроек и все три поля обязательны.

| Настройка | Тип |
| --- | --- |
| `level` | Одна из пяти строк уровня в нижнем регистре |
| `prefixes` | Плотный массив непустых строк; для отсутствия префиксов передаётся `{}` |
| `write` | Функция, принимающая одну готовую строку; для стандартного вывода передаётся `print` |

Отсутствие таблицы настроек или любого обязательного поля, `nil`, неверный тип или неизвестный уровень — ошибка использования API через `assert`/`error` со строкой. Неизвестные имена настроек также отклоняются, чтобы опечатки не оставались незаметными.

Пакет не добавляет имя конкретного мода самостоятельно. Потребитель задаёт его первым префиксом.

Конструктор копирует массив префиксов, сохраняет функцию вывода по ссылке и не меняет таблицу настроек. Методов изменения настроек нет; прямое изменение внутренних полей экземпляра не является публичным API. Загрузка через `require` и создание экземпляра ничего не выводят.

### Сообщения

Публичные методы: `log:trace(message, fields?)`, `log:debug(message, fields?)`, `log:info(message, fields?)`, `log:warning(message, fields?)`, `log:error(message, fields?)`.

- `message` — обязательная строка, в том числе пустая.
- `fields` — необязательная таблица со строковыми ключами; отсутствие или `nil` означают отсутствие полей. Пустые строковые ключи допускаются.
- Значение каждого поля преобразуется одним вызовом `tostring(value)`. Таблица полей и сами значения не изменяются.
- Поля выводятся в порядке `table.sort` для строковых ключей, независимо от порядка вставки. Пакет использует обычную сортировку среды без собственного сравнения или локализации.
- Присваивание `nil` удаляет поле по правилам Lua; специального маркера для него нет.
- Методы возвращают `nil`. Метод `error` только пишет сообщение и не возбуждает исключение по своему уровню.

Порядок важности: `trace < debug < info < warning < error`. Выводятся сообщения с уровнем не ниже установленного порога. Для подавленного сообщения метод сразу возвращает `nil`: аргументы не проверяются и не обходятся, `tostring` и `write` не вызываются. Вычисление аргументов до вызова метода подчиняется обычным правилам Lua; ленивых функций в API нет.

Для разрешённого сообщения неверные типы `message`, `fields` или ключей полей считаются ошибкой использования API. Ошибки пользовательского `__tostring` и функции `write` распространяются вызывающему коду; пакет не подменяет их другим сообщением и не пробует вывести лог повторно. Вся строка формируется до единственного вызова `write`, поэтому сбой преобразования не отправляет частично собранную строку.

### Производные экземпляры

`log:with_prefix(prefix, ...)` принимает одну или несколько непустых строк и возвращает новый экземпляр. Без аргументов, при `nil` в любой позиции или другом типе возникает ошибка использования API.

Префиксы добавляются в порядке аргументов после всех прежних префиксов. Повторения сохраняются. Уровень и функция вывода наследуются без изменений; переопределение этих настроек через `with_prefix` не входит в контракт. Для другого порога или другой функции вывода используется `logger.new(...)`.

У нового экземпляра собственный массив префиксов; исходный экземпляр и соседние производные экземпляры не изменяются. Ссылка на функцию вывода может быть общей.

### Формат

**Пример:**

```lua
local logger = require("limanchel.pkg.logger.v0_1_0.logger")
local log = logger.new({ level = "debug", prefixes = { "ASS" }, write = print })
local filters_log = log:with_prefix("storage", "filters")

filters_log:info("Предмет отклонён", { item_id = 42, reason = "blacklist" })
```

Результат, переданный в `write`:

```text
[ASS][storage][filters][INFO] Предмет отклонён {item_id = 42; reason = blacklist}
```

Префиксы и уровень заключены в квадратные скобки без промежутков между ними. Уровень всегда выводится заглавными буквами последним элементом перед сообщением. Без префиксов строка начинается с `[INFO]` или соответствующего уровня. После уровня всегда один пробел, затем сообщение.

Блок полей добавляется только при наличии полей: один пробел, `{`, пары `ключ = значение` через `; `, `}`. Пустая таблица не добавляет `{}`. Кавычки вокруг значений не добавляются.

Чтобы одна запись занимала одну строку, символы CR и LF в префиксах, сообщении, ключах и результатах `tostring` заменяются видимыми последовательностями `\r` и `\n`. Остальные символы, включая скобки, точки с запятой и обратную косую черту, сохраняются. Формат предназначен для чтения человеком; обратимый разбор не обещается. Пакет не добавляет завершающий перевод строки: это ответственность `write`, включая стандартный `print`.

## Размещение и среда

- Первая версия: `0.1.0`, каталог `Lua/limanchel/pkg/logger/v0_1_0/`.
- Публичная точка входа `logger.lua`, определения API `logger.d.lua`, контракт и примеры в `README.md`, тесты рядом в `logger_test.lua`.
- Модуль возвращает таблицу API; экземпляры создаёт `logger.new(...)`. Имена функций и методов — `snake_case` по соглашениям проекта.
- Lua 5.2, включая MoonSharp/LuaCs; клиент и сервер. Внешних пакетов, игрового API и C#-моста не требуется.
- Отдельной зависимости от `goerrors` нет: совместимость встроенных ошибок обеспечивается их `__tostring`.

## Проверка и свобода реализации

Проверки контракта должны охватывать обязательность таблицы настроек и каждого её поля, все пары порога и уровня, формат и сортировку полей, стандартное и пользовательское преобразование значений, отсутствие работы с подавленными сообщениями, наследование и независимость экземпляров, сохранение явно переданной функции вывода, ошибки вызовов и распространение сбоев `__tostring`/`write`. Для вывода использовать функцию, собирающую строки, без запуска игры.

После изменения Lua обязательны проектные форматирование и линт. Игровую проверку консоли следует отличать от проверок чистого Lua: последние подтверждают переданную строку, но не внешний вид консоли конкретной версии игры.

Внутреннюю организацию функций и классов, имена вспомогательных функций и разбиение тестов выбирает исполнитель. Дополнительные публичные методы, альтернативные форматы и новые настройки не требуются.
