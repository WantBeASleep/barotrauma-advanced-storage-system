# Ведение документации

- Пиши предельно ёмко: без повторов, очевидных пояснений и вводной воды.
- Развивай документацию постепенно, по одной фиче. Не переноси архив целиком.
- `archive` — источник контекста. Старые решения сверяй с текущим обсуждением; противоречия подсвечивай.
- Каждой фиче — папка в `docs/features`. Отдельным связным темам — отдельные файлы, по необходимости.
- Порядок знакомства с модом — в [оглавлении фич](features/README.md). При добавлении или переносе фич обновляй ссылки и порядок чтения в нём.
- Разделяй назначение, настройки и поведение короткими смысловыми блоками. Важные опции выделяй отдельно.
- Примеры добавляй только для неочевидных случаев и начинай с **«Пример:»**.
- Используй термины из `docs/glossary.md`. Новые определения согласовывай.
- Предложения и открытые вопросы отделяй от принятых решений. Не добавляй техническую архитектуру без необходимости.
- Не вводи графы, обязательные шаблоны и дополнительные документы без конкретной пользы.
