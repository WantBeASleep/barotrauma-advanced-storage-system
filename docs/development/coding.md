# Соглашения по написанию кода

## Lua first

Основную логику, состояние мода и управление выполнением держи в Lua. C# используй для отдельных операций, требующих высокой производительности или недоступных из Lua из-за ограничений платформы. C# остаётся исполнителем под управлением Lua: избегай переноса в него игровой логики, состояния мода и управляющих решений.

## Чистая архитектура

Строй мод по принципам чистой архитектуры: разделяй код на модули с чёткой зоной ответственности и взаимодействием через явные контракты. Изолируй игровую логику мода от UI, хранения данных и интеграции с Barotrauma/LuaCs. Направляй зависимости к игровой логике: внешние компоненты реализуют нужные ей контракты, а она не зависит от деталей их реализации.

## Выполнение

- Lua-код рассчитан на Lua 5.2 через LuaCsForBarotrauma/MoonSharp.
- Разделяй клиентский, серверный и общий код. Используй API только на предназначенной для него стороне.
- При написании Lua-кода применяй [lua-style](../../.codex/skills/lua-style/SKILL.md).

## Форматирование и линтинг

- Изменённый Lua-код должен успешно проходить сначала форматирование через `luafmt`, затем проверку через `lualint`. Исправляй выявленные ошибки до завершения работы.
- После изменения настроек или инструментов форматирования запускай форматирование.
- После изменения настроек линтера, сгенерированных std-файлов или инструментов линтинга запускай линт.
- Исключай сгенерированный Lua-код через `.styluaignore`, если форматирование может его повредить.
- Для изменений только документации форматирование и линт Lua не требуются.

Команды запуска — в [tooling.md](tooling.md).
