# logger 0.1.0

Читаемые цветные сообщения с уровнем и префиксами для передачи настроенного логгера как зависимости.

Источник: [репозиторий мода](https://github.com/WantBeASleep/barotrauma-advanced-storage-system), каталог `Lua/limanchel/pkg/logger/v0_1_0/`. Требуется Lua 5.2 через LuaCs, клиент или сервер. Игровой `Color` из общей библиотеки LuaCs должен быть доступен до загрузки модуля. Других пакетов и собственного C#-кода не требуется. Загрузка модуля и создание экземпляра ничего не выводят.

## Создание и уровни

`logger.new(options)` возвращает независимый экземпляр. Все три поля обязательны, значений по умолчанию нет:

- `level` — `trace`, `debug`, `info`, `warning` или `error`.
- `prefixes` — плотный массив непустых строк; `{}` означает отсутствие префиксов.
- `write(line, color)` — функция вывода. Получает ровно два аргумента: готовую строку без завершающего перевода строки и `Microsoft.Xna.Framework.Color` для всей записи. Функция применяет цвет при выводе и не должна менять полученный объект цвета. Прямой `print` этому контракту не соответствует.

Массив префиксов копируется, `write` сохраняется по ссылке. Последующее изменение таблицы настроек не влияет на экземпляр. Неизвестные настройки, отсутствие обязательных значений и неверные типы вызывают строковую ошибку Lua. Настройки существующего экземпляра не меняются через публичный API.

**Пример:** вызывающий код передаёт готовую функцию консольного вывода `write(line, color)`.

```lua
local logger = require("limanchel.pkg.logger.v0_1_0.logger")

local function report_opened(write)
   local log = logger.new({ level = "info", prefixes = { "ASS", "storage" }, write = write })
   log:info("Хранилище открыто")
end
```

```text
[ASS][storage][INFO] Хранилище открыто
```

Методы `trace`, `debug`, `info`, `warning`, `error` принимают строку сообщения, в том числе пустую, и необязательную таблицу `fields`. Выводятся уровни не ниже порога в порядке `trace < debug < info < warning < error`. Все методы возвращают `nil`; `error` только выводит сообщение. Подавленный вызов не проверяет и не обходит аргументы, не вызывает `tostring` и `write`; аргументы до вызова вычисляются обычным образом в Lua.

## Цвета

Палитра зашита в пакет и создаётся при его загрузке. Цвет выбирается по уровню самого сообщения; настройки палитры и бесцветного режима нет.

| Уровень | Игровой цвет |
| --- | --- |
| `trace` | `Color.Beige` |
| `debug` | `Color.LimeGreen` |
| `info` | `Color.SkyBlue` |
| `warning` | `Color.Orange` |
| `error` | `Color.Red` |

Вся запись, включая префиксы и поля, получает один цвет. Текст не содержит ANSI-последовательностей или цветовой разметки. Подключение конкретного механизма консольного вывода через `write` выполняет потребитель.

## Поля и формат

Ключи `fields` — строки, в том числе пустые; они сортируются обычным `table.sort`. Ключи и значения сохраняются из одного обхода штатным `pairs`, включая результат `__pairs`, без повторного чтения исходной таблицы. Каждое значение преобразуется одним штатным `tostring`, с учётом `__tostring` и стандартного представления Lua без него. Обычный метод объекта `tostring()` не вызывается; вложенные таблицы и циклы не раскрываются. Поля со значением `nil` отсутствуют по правилам Lua. Таблица полей и значения не изменяются логгером.

**Пример:**

```lua
log:info("Предмет отклонён", { item_id = 42, reason = "blacklist" })
```

```text
[ASS][storage][INFO] Предмет отклонён {item_id = 42; reason = blacklist}
```

Префиксы и уровень идут в `[]` без промежутков, затем один пробел и сообщение. Непустые поля добавляются после пробела в `{}`, пары разделяются `; `, ключ и значение — ` = `. Кавычки вокруг значений не добавляются; без полей, при `nil` и `{}` блок отсутствует.

CR и LF во всех текстовых компонентах заменяются видимыми `\r` и `\n`; остальные символы сохраняются. Обратимый разбор формата не обещается. Завершающий перевод строки добавляет функция вывода, если он нужен.

Для разрешённого сообщения неверные типы сообщения, таблицы полей или её ключей вызывают строковую ошибку Lua. Сбои `__tostring` и `write` передаются вызывающему коду без подавления и повторных попыток. Строка полностью формируется до единственного `write(line, color)`, поэтому ошибка преобразования не отправляет её частично. Результаты `write` игнорируются.

## Производные логгеры

`log:with_prefix(prefix, ...)` возвращает независимый экземпляр с прежним порогом и той же функцией `write`. Принимает одну или несколько непустых строк, дописывает их после прежних префиксов в порядке аргументов, сохраняя повторения. Исходный экземпляр и соседние производные экземпляры не меняются. Отсутствие аргументов, `nil` в любой позиции и неверные типы вызывают строковую ошибку Lua.

**Пример:**

```lua
local logger = require("limanchel.pkg.logger.v0_1_0.logger")

local function report_rejection(write)
   local log = logger.new({ level = "debug", prefixes = { "ASS" }, write = write })
   local filters_log = log:with_prefix("storage", "filters")
   filters_log:info("Предмет отклонён", { item_id = 42, reason = "blacklist" })
end
```

```text
[ASS][storage][filters][INFO] Предмет отклонён {item_id = 42; reason = blacklist}
```

Имя мода пакет не добавляет самостоятельно. Для другого порога или другой функции вывода создаётся отдельный экземпляр через `logger.new(...)`.

## Изменения

0.1.0 — первая версия: пять уровней с фиксированными игровыми цветами, явные настройки, структурные поля, производные экземпляры с префиксами.

При доработке невыпущенной версии без клиентов контракт вывода по разрешению автора изменён с `write(line)` на `write(line, color)`, добавлена зависимость от LuaCs. Имя импорта сохранено. Для перехода требуется цветная функция вывода вместо прежнего `write` или прямого `print`.
