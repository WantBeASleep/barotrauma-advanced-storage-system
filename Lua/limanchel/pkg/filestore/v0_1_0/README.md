# filestore 0.1.0

Общий пакет локального хранения текстовых файлов по относительным ключам. Источник исходников — этот репозиторий, каталог `Lua/limanchel/pkg/filestore/v0_1_0/`. Начальная версия; миграция с прежнего API не требуется.

Требуются Lua 5.2/MoonSharp, встроенные `Game` и `File` LuaCsForBarotrauma и точная зависимость `limanchel.pkg.goerrors.v0_1_0.goerrors`. Пакет работает на клиенте и сервере независимо, без сети и собственного C#-моста. Проверяемая платформа — LuaCs 1.0.117 для Barotrauma 1.13.5.0.

## Загрузка

`require("limanchel.pkg.filestore.v0_1_0.filestore")` не обращается к диску, не создаёт каталоги и не требует настройки. `load(key)` читает текущий файл при каждом вызове, поэтому видит ручные изменения. Успех — строка, включая пустую; ожидаемый сбой — `nil, err`.

Корень — `<Game.SaveFolder>/ModFiles/`. На Windows стандартный путь — `%LocalAppData%/Daedalic Entertainment GmbH/Barotrauma/ModFiles/`; при пользовательском пути сохранений используется он. Каталог и файлы доступны через проводник. Изменение `Game.SaveFolder` влияет на следующую операцию; переноса старых файлов нет.

## Ключи

Ключ — непустой относительный путь с разделителем `/` и именем файла в конце. Запрещены абсолютные пути, обратный слеш, пустые сегменты, `.` и `..`, управляющие символы, `< > : " | ? *`, завершающие сегмент пробелы/точки и Windows-имена устройств, включая варианты с расширением и COM/LPT с надстрочными цифрами ¹/²/³. Суффикс `.filestore-tmp` зарезервирован без учёта регистра во всех сегментах.

Ключ не исправляется автоматически и сохраняет регистр. Используй одно написание: чувствительность к регистру зависит от ОС. Первые каталоги выбирает потребитель; пакет не добавляет имя мода или сторону выполнения.

## Ошибки

Неверные типы аргументов и недопустимые ключи вызывают строковый `assert` до дисковых операций. Ожидаемые сбои возвращают объект `goerrors`; пакет не логирует и не выбирает запасные пути.

`filestore.errors.not_found` соответствует результату `File.Exists == false`: он не гарантирует различение отсутствующего файла и всех причин недоступности на уровне ОС. `read_failed` означает исключение при определении пути, проверке наличия или чтении; исчезновение файла после проверки может дать эту причину. `write_failed` зарезервирован для сохранения. Объекты причин не изменяй.

**Пример:** чтение с проверкой отсутствия файла.

```lua
local filestore = require("limanchel.pkg.filestore.v0_1_0.filestore")
local goerrors = require("limanchel.pkg.goerrors.v0_1_0.goerrors")

local text, err = filestore.load("ass/storagecfgs/cfg1.json")
if not text then
   if goerrors.is(err, filestore.errors.not_found) then
      print("Файл пока не сохранён")
   else
      print(err:error())
   end
end
```
