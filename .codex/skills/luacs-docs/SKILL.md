# LuaCs Docs

LuaCsForBarotrauma — платформа, на которой разрабатывается мод. Этот навык отвечает за получение документации по любому аспекту платформы, включая Lua, C#, игровые сущности, подключение и загрузку модов, конфигурацию, установку, сборку и диагностику.

При вопросе о платформе найди и прочитай соответствующий источник до принятия решения. Получи контекст: назначение механизма или сущности, условия применения, связи и контракт. Не придумывай поведение по названию или памяти. Отсутствие темы в краткой карте ниже не ограничивает область навыка: используй общий поиск по документации.

## Как получать контекст

1. Сформулируй вопрос к платформе и выбери ветку документации. Различай Lua-скрипт, C#-исходники, готовую сборку, взаимодействие языков, настройку среды и конкретный API. Определи нужную сторону выполнения; если вопрос касается обеих, проверь обе.
2. Для механизма платформы начни с руководства; для символа — с индекса типов/членов нужной стороны или Lua Code. Перейди к связанным типам, конфигурации и этапам жизненного цикла, если без них поведение непонятно.
3. Извлеки сведения по вопросу:
   - для подключения и настройки — необходимые файлы, формат параметров, значения по умолчанию, условия включения, порядок загрузки и зависимости;
   - для сборки и установки — соответствие версии игры/платформы, целевой среды, инструментов и зависимостей;
   - для диагностики — источник сообщения, этап сбоя и документированные средства проверки;
   - для API — сведения ниже.

Перед использованием API выясни:

- точную сигнатуру и нужную перегрузку, типы аргументов и результата;
- статический это вызов или работа с экземпляром, как он вызывается из нужного языка;
- где и когда он доступен: клиент, сервер, одиночная игра, этап жизненного цикла;
- условия вызова, допустимость отсутствующих значений, побочные эффекты и необходимость синхронизации;
- для хука — событие, параметры обработчика и смысл возвращаемого значения; для коллекции — её тип и способ обхода.

Если страница только перечисляет имена или помечена `Incomplete`, продолжи по связанным страницам и исходникам соответствующей версии. Отсутствие ограничения в кратком справочнике не доказывает, что ограничения нет.

Применяй найденные сведения к задаче. В ответе кратко укажи использованные страницы и существенные неподтверждённые предположения. Отличай требования платформы от выбранных настроек проекта; не превращай пример нового мода в обязательную перестройку существующего.

Уже прочитанный и подходящий по версии контекст можно использовать повторно. При изменении используемого API или появлении противоречия открой источник снова. Механическая правка, не затрагивающая контракт платформы, не требует обхода справочника.

## Если темы нет в карте

1. Сформулируй поисковые слова: точное имя класса/метода, XML-ключ, имя конфигурационного файла, текст ошибки либо английское название механизма. Для подключения C# это могут быть `in-memory`, `assembly`, `IAssemblyPlugin`, `RunConfig`.
2. Пройди оглавление подходящей ветки. Для C# используй индексы классов, пространств имён, членов и иерархию; для Lua — Manual и Code. Ссылки на индексы находятся в карте.
3. Если поиск сайта не помогает, ищи по всему `site:evilfactory.github.io/LuaCsForBarotrauma/ <тема>`, затем сузь до Lua, C#, клиента или сервера. Не ограничивай все запросы каталогом `lua-docs`.
4. Открой саму страницу, проверь связанные разделы и определения. Поисковый сниппет не заменяет чтение.
5. Если ответа в опубликованной документации нет, ищи тему в документации и исходниках репозитория нужной версии. Для ключа конфигурации найди чтение/разбор ключа, для поведения API — реализацию и места вызова. Скажи, что ответ установлен по исходникам, а не описан в руководстве.

Новая или отсутствующая в карте сущность ищется тем же способом. Не объявляй функцию неподдерживаемой только потому, что её нет в Lua-индексе, и не объявляй её доступной из Lua только потому, что она есть в C#.

## Как читать справочники

- `Manual` объясняет механизмы и даёт примеры; `Code` описывает функции, поля и типы. Пример помогает понять применение, но не заменяет проверку сигнатуры.
- В C#-справочнике выбери Client или Server. На странице типа читай наследование, конструкторы, методы, свойства, поля, события и `List of all members`; переходи по `Definition ... of file` к исходнику. Для общего кода сравни обе стороны.
- Если страница выглядит пустой или меню не попало в текст, открой прямой индекс из карты. При необходимости извлеки ссылки из HTML; навигация Doxygen может находиться в подключённых `navtreedata.js`/`menudata.js`. Не считай отсутствие текста меню отсутствием документации.
- На странице `Hook` есть и методы регистрации, и каталог игровых событий. Сигнатура `Hook.Add` не описывает аргументы обработчика конкретного события: найди само событие.
- Читай все подходящие перегрузки. Одно имя метода или якорь страницы не гарантирует единственную сигнатуру.
- Различай класс, экземпляр, prefab, компонент и коллекцию. `ItemPrefab` и `Item` требуют разных операций; C#-коллекция не обязательно ведёт себя как Lua-таблица.
- Следуй реальным ссылкам индекса: имя Lua API может отличаться от полного C#-имени. Не конструируй URL класса догадкой.

## Неполная документация и версии

Выясни версию установленной платформы и игры по доступным данным, когда от неё зависит ответ. Онлайн-справочник, пример и текущая ветка репозитория могут отличаться от установленной версии. Не смешивай их настройки и сигнатуры молча; `Generated by Doxygen` обозначает версию генератора документации, а не платформы.

Если документации недостаточно, ищи точное имя в исходниках соответствующей версии. Проверяй также регистрацию и экспорт типа в Lua: наличие C#-метода само по себе не подтверждает его доступность из Lua. Аннотации и соседний код помогают найти контракт, но не отменяют расхождение с реализацией.

Если сайт недоступен, используй локальную копию документации, установленные файлы платформы или доступные исходники. Явно отделяй подтверждённое поведение от предположений; не называй платформу проверенной по одному примеру чужого мода.
