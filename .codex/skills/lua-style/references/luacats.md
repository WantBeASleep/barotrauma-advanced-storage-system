# LuaCATS: справочник для агента

LuaCATS — аннотации Lua Language Server (LuaLS) для типов, автодополнения, документации и диагностики. Это комментарии: они не создают классы, не преобразуют значения и не проверяют типы при исполнении. С LuaLS 3 формат не полностью совместим с EmmyLua; синтаксис LDoc не подставляй вместо LuaCATS.

Источники: [аннотации](https://luals.github.io/wiki/annotations/), [файлы определений](https://luals.github.io/wiki/definition-files/), [исходник справочника](https://github.com/LuaLS/LuaLS.github.io/blob/main/src/content/wiki/annotations.mdx). Ниже охвачены все 25 аннотаций официального перечня. Для возможностей с указанной минимальной версией проверяй установленную версию LuaLS.

## Запись комментариев

- Аннотация: `---@тег аргументы`. Ставь блок непосредственно перед описываемым объявлением; имена параметров должны совпадать с кодом.
- Описание: `---Текст`. Поддерживаются Markdown-заголовки, выделение, зачёркивание, списки, цитаты, код и блоки кода, разделители, ссылки и изображения.
- Строка `---` разделяет абзацы. Для переноса внутри абзаца используй `<br>`; допустимы `\n`, два конечных пробела и Markdown `\`, но последние два варианта ненадёжны при форматировании.
- После типа и имени можно писать описание. У `@return` комментарий без имени отделяй `#`: `---@return boolean # Признак успеха.`
- В VS Code ввод `---` над функцией предлагает шаблон параметров и результатов; проверь автоматически предложенные типы.

## Типы

Базовые типы: `nil`, `any`, `boolean`, `string`, `number`, `integer`, `function`, `table`, `thread`, `userdata`, `lightuserdata`. LuaLS понимает их независимо от выбранной версии Lua; это не добавляет соответствующие возможности в runtime. Предпочитай конкретные типы вместо `any`, `table` и `function`, когда контракт известен.

| Форма | Значение / пример |
|---|---|
| `T?` | `T` или `nil`; эквивалент `T\|nil` |
| `A\|B` | Объединение альтернативных типов |
| `"ready"`, `0`, `true` | Литеральные типы — конкретные значения |
| `T[]` | Массив элементов `T` |
| `(A\|B)[]` | Массив смешанных элементов; скобки относятся к объединению |
| `[string, integer]` | Кортеж — таблица с позиционными элементами; не несколько возвращаемых значений |
| `table<K, V>` | Таблица с ключами `K` и значениями `V` |
| `{ [string]: integer }` | Таблица с типизированным индексом |
| `{ name: string, count: integer }` | Структура таблицы без отдельного имени класса |
| `fun(x: string): boolean` | Тип функции с параметрами и результатом |
| `fun(x: string, limit?: integer, ...: number): boolean, string?` | Необязательный параметр, varargs и несколько результатов |
| `Box<integer>` | Подстановка аргумента в обобщённый тип |

Типы, объявленные через `@class`, `@alias` и `@enum`, используются в тех же позициях, что и базовые типы. `integer` — целочисленный тип, `number` допускает и дробные числа. `?` допускает `nil`, но не задаёт значение по умолчанию.

## Переменные, псевдонимы и перечисления

- `---@type T` задаёт тип следующей переменной. Это не объявление нового типа и не способ добавлять поля существующему классу; поля описывай в блоке `@class` / `@field`.
- `---@alias Name T` создаёт именованный тип без runtime-объекта. Для набора вариантов используй объединение литералов или продолжения `---|` с описаниями.
- `---@enum Name` перед реальной таблицей создаёт тип из её значений. `---@enum (key) Name` создаёт тип из ключей. Таблица остаётся обычным объектом Lua.

```lua
---@alias ItemId integer
---@alias AccessMode
---| '"read"' # Только чтение.
---| '"write"' # Запись.

---@type table<ItemId, string>
local names = {}

---@enum Status
local status = { pending = 0, ready = 1 }

---@enum (key) Direction
local direction = { left = -1, right = 1 }
-- Тип Direction принимает "left" или "right".
```

Литеральные значения существующих символов можно ссылочно включать в тип через обратные кавычки:

```lua
local READ = 1
local WRITE = 2
---@alias AccessFlag `READ` | `WRITE`
```

Варианты для подсказок также можно дописать строками `---|` после `@param`; ссылку на символ записывай как ``---| `READ` # Чтение.``.

## Классы, поля и видимость

- `---@class Name` объявляет тип структуры; `---@class Child: Parent, OtherParent` — наследование от одного или нескольких типов. Аннотация не реализует наследование в Lua.
- `---@class (exact) Name` запрещает добавление необъявленных полей по правилам LuaLS.
- `---@field name T Описание` добавляет поле в непосредственно предшествующий блок `@class`; `name?` делает поле необязательным.
- `---@field [string] T` задаёт тип значений для произвольных строковых ключей. Именованные поля пиши перед индексным полем. Квадратные скобки здесь — часть синтаксиса.
- Перед именем поля допустимы `public`, `private`, `protected`, `package` (LuaLS 3.6+). Без модификатора поле публичное.

| Доступ | Поле | Метод / функция | Область доступа |
|---|---|---|---|
| Публичный | `---@field public name T` | Без ограничивающей аннотации | Откуда угодно |
| Приватный | `---@field private name T` | `---@private` | Внутри своего класса, не в наследниках |
| Защищённый | `---@field protected name T` | `---@protected` | Внутри своего класса и наследников |
| Файловый | `---@field package name T` | `---@package` | Только в файле определения, не во всей папке или пакете |

```lua
---@class (exact) Storage
---@field capacity integer
---@field label? string
---@field private items string[]
local Storage = {}

---@private
---@return integer
function Storage:count_internal() end
```

Все ограничения видимости проверяет анализатор; Lua по-прежнему разрешает обычный доступ к полям.

## Функции

- `---@param name T Описание` описывает параметр; `name?` разрешает его пропуск / `nil`.
- `---@param ... T` описывает каждый дополнительный аргумент `...`.
- `---@return T name Описание` описывает результат; имя и описание необязательны. Несколько результатов задавай отдельными `@return` в порядке возврата либо списком типов через запятую.
- `---@return T ...` описывает переменное число результатов типа `T`, а не массив.
- `---@overload fun(x: T): R` добавляет сигнатуру; можно повторять. Также описывает вызов объекта с `__call`. Это описание существующего поведения, не реализация диспетчеризации.
- `---@nodiscard` требует использовать возвращаемые значения функции; игнорирование вызывает диагностику.
- `---@async` помечает асинхронную функцию для диагностики группы `await` и подсказок при `hint.await = true`; не запускает корутину и не добавляет ожидание.
- `---@deprecated` помечает устаревшую функцию; укажи замену в описании.
- `---@vararg T` — устаревшая совместимость с EmmyLua; в новом коде используй `---@param ... T`.

```lua
---Ищет имя по идентификатору.
---@param id integer
---@param fallback? string
---@return string? name Имя или nil, если запись отсутствует.
---@nodiscard
local function find_name(id, fallback) end

---@param ... string
---@return integer count
---@return string ...
local function collect_names(...) end
```

Для callback используй тип `fun(...)`. В поле, представляющем метод с вызовом через `:`, явно укажи `self`: `---@field get_count fun(self: Storage): integer`. В обычном `function Storage:get_count()` параметр `self` уже неявный.

В `.d.lua` для подробных описаний перегрузок допустимы несколько пустых объявлений одной функции, каждое со своими `@param` / `@return`. В исполняемом `.lua` повторное объявление заменит функцию: используй `@overload`. У LuaLS есть ограничения сужения типов при перегрузках; не считай альтернативные сигнатуры доказательством всех связей между результатами. Например, `T|nil` и `string?` описывают два отдельных результата, но сами по себе не выражают «ровно один из них не nil».

## Generics

`---@generic T` вводит параметр типа для сигнатуры; `---@generic T: Parent, U` ограничивает `T` и объявляет `U`. Используй один параметр типа в аргументе и результате, чтобы сохранить их связь:

```lua
---@generic T
---@param value T
---@return T
local function identity(value) end

---@class Box<T>
---@field value T
---@field get fun(self: Box<T>): T

---@type Box<integer>
local box
```

Захват имени типа из строкового аргумента использует обратные кавычки вокруг generic-параметра:

```lua
---@class Widget

---@generic T
---@param class_name `T`
---@return T
local function create(class_name) end

local widget = create("Widget") -- Тип результата: Widget.
```

Без обратных кавычек `---@param class_name T` связывает результат с типом самого аргумента, а не с классом, названным строкой.

Для LuaLS 3.17.0+ документация отдельно подтверждает параметры классов, наследование от подставленного generic-типа (`---@class IntBox: Box<integer>`), generic-параметры в `@overload` и inline-типы `fun<T>(value: T): T` в `@field` / `@type`. Для подстановки через наследование объявляй члены generic-класса через `@field`: отдельно объявленный метод с `---@return T` не получает ту же подстановку через класс-наследник. Generics развиваются; сложные случаи проверяй установленным LuaLS.

## Уточнение типов

- `---@cast value T` уточняет тип уже существующей переменной в месте аннотации.
- `---@cast value +T` добавляет альтернативу, `-T` удаляет; допускается список `+T, -U`.
- `---@cast value +?` добавляет `nil`, `-?` убирает его.
- `value --[[@as T]]` задаёт тип выражения. Строчная запись `---@as T` неверна. Для массива используй `value --[=[@as string[]]=]`, чтобы скобки типа не закрыли комментарий раньше времени.

```lua
---@type string|integer|nil
local value
---@cast value -nil, -integer
-- Далее LuaLS рассматривает value как string.
```

`@cast` и `@as` не проверяют и не преобразуют значение. Применяй только при известном контракте, который анализатор не вывел; если тип неизвестен, сначала проверь значение кодом.

## Операторы

`---@operator operation(Operand): Result` в блоке класса описывает тип результата оператора; для унарного оператора скобки можно опустить. Имя операции соответствует метаметоду без `__`, например `add`, `sub`, `mul`, `div`, `mod`, `pow`, `unm`, `len`, `concat`. Аннотация не создаёт метаметод.

```lua
---@class Vector
---@operator add(Vector): Vector
---@operator unm: Vector
---@operator len: number
```

`---@operator call: Result` допустим, но для полной сигнатуры `__call` предпочитай `---@overload fun(...): Result`. Не переноси сюда синтаксис `fun()` для обычных операторов.

## Модули и определения

- `---@meta` помечает файл определений. Пиши его в начале `.d.lua`; тела функций оставляй пустыми. Именование `.d.lua` рекомендовано LuaLS и обязательно по этому скиллу.
- `---@meta module.name` привязывает определение к конкретному имени для разрешения `require` в LuaLS. `---@meta _` делает файл недоступным для такого разрешения; подходит для определений глобальных API.
- В meta-файлах автодополнение не показывает контекст, hover над `require` показывает `[meta]` вместо пути, а поиск ссылок игнорирует meta-файлы.
- Подключай внешние определения через `workspace.library` (в настройках VS Code — `Lua.workspace.library`). Суффикс `.d.lua` сам по себе не гарантирует, что анализатор выберет нужное определение модуля: проверь разрешение имени.
- `---@module 'module.name'` имитирует `require` для анализатора. Перед локальной переменной задаёт ей тип результата импорта; самостоятельно сообщает анализатору о подключении модуля. Это не LDoc-тег с именем текущего модуля и не runtime-импорт.

```lua
---@meta example.storage

local storage = {}

---@param id integer
---@return string?
function storage.get_name(id) end

return storage
```

В отдельном файле, если runtime уже предоставляет объект другим способом:

```lua
---@module 'example.storage'
local storage
-- Только модель импорта для LuaLS; при исполнении storage здесь равен nil.
```

Не исполняй `.d.lua`; синхронизируй его API с реализацией. Не создавай несовместимые повторные определения одного типа в нескольких файлах.

## Диагностика и версии

`---@diagnostic состояние: код1, код2` управляет конкретными предупреждениями:

| Состояние | Действие |
|---|---|
| `disable-next-line` | Отключить для следующей строки |
| `disable-line` | Отключить для текущей строки |
| `disable` | Отключить в файле / далее до соответствующего `enable` |
| `enable` | Включить обратно |

```lua
---@diagnostic disable-next-line: unused-local
local reserved = 1
```

Коды бери из [справочника диагностик](https://luals.github.io/wiki/diagnostics/). Подавляй конкретное известное исключение на минимальном участке; не используй подавление вместо корректного описания API.

`---@version 5.4` у функции или класса указывает требуемую версию Lua. Допускаются `5.1`, `5.2`, `5.3`, `5.4`, `JIT`, префиксы `<` / `>` и список через запятую, например `---@version >5.2, JIT`. Это ограничение версии Lua, не LuaLS; оно не переключает интерпретатор.

## Ссылки и навигация

- `---@see Symbol` добавляет ссылку на символ проекта.
- `[подпись](lua://Symbol)` внутри `---` делает то же в Markdown-описании (LuaLS 3.9.2+).
- `---@source path` перенаправляет переход к определению на другой исходник. Допустимы относительный или абсолютный путь, URI `file:///...`, суффиксы `:строка` и `:строка:столбец`.

```lua
---См. [хранилище](lua://Storage).
---@see Storage
---@source native/storage.cpp:42:1
---@return integer
local function get_capacity() end
```
