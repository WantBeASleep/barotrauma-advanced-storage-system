# Скрипты проекта

Пиши вспомогательные утилиты на Python. Перед изменением изучи существующий скрипт, его README и принятые в проекте способы запуска и подключения зависимостей. Сохраняй совместимость командной строки, если задача не требует её изменения.

## Размещение

- Каждую самостоятельную утилиту размещай в отдельной папке с понятным именем и `README.md` рядом с основным скриптом. Вспомогательные модули одной утилиты могут лежать в той же папке.
- Используй существующий каталог проектных инструментов; не переноси соседние утилиты ради единообразия.
- Храни необходимые ресурсы внутри дерева проекта. При переносе обновляй ссылки, команды запуска и определение путей.

## Язык документации

- Пиши README, docstring, поясняющие комментарии и встроенную пользовательскую документацию на русском языке.
- В `-h` / `--help` на русском должны быть назначение, описания аргументов, примеры, пояснения значений по умолчанию и стандартные подписи справки, включая описание самого `--help`. Не оставляй справку смешанной из-за английских текстов `argparse`; используй публичные настройки парсера или локализацию без подмены внутренних функций библиотеки.
- Имена файлов, идентификаторы кода, флаги CLI и названия внешних API сохраняй в принятом техническом формате; переводить их не нужно.
- Собственные сообщения пользователю, включая ошибки и итоги работы, также пиши по-русски.

## Командная строка и выполнение

- Используй `argparse` с поддержкой `-h` и `--help`. Описывай все публичные аргументы, ограничения и значения по умолчанию, влияющие на результат.
- Отделяй разбор аргументов от основной логики. Запускай работу через `main()` под `if __name__ == "__main__":`; импорт модуля не должен запускать обработку или менять файлы.
- Справка должна работать без входных файлов, записи на диск и загрузки необязательных зависимостей, нужных только для обработки.
- Проверяй входные данные до записи результатов. Ожидаемые ошибки объясняй кратко и завершай процесс с ненулевым кодом; не скрывай неожиданные исключения общим перехватом.
- Для изменения, удаления или перезаписи существующих данных добавляй `--dry-run`: показывай план с теми же правилами отбора и проверки, но без записей, удаления и создания каталогов. Для простой генерации новых файлов достаточно явного выходного пути.
- Сделай поведение при повторном запуске и существующих выходных файлах явным. Для необратимого удаления или перезаписи предусматривай явный флаг либо другой документированный способ выбора такого поведения.

## Пути и зависимости

- Используй `pathlib.Path`; не зашивай машинозависимые абсолютные пути.
- Встроенные ресурсы и проектные пути по умолчанию вычисляй от `Path(__file__).resolve().parent` или корня проекта, а не от текущего рабочего каталога.
- Определяй корень только при необходимости: используй известную структуру каталогов либо устойчивый признак проекта, например `filelist.xml`. Не копируй произвольный `parents[N]`; при поиске корня обрабатывай отсутствие признака понятной ошибкой.
- Относительные пути, переданные пользователем, по умолчанию отсчитывай от текущего рабочего каталога. Если проект использует другую базу, сохрани её и укажи в README и справке.
- Для текстовых файлов явно задавай кодировку, обычно UTF-8; при работе с существующими данными соблюдай их формат.
- Предпочитай стандартную библиотеку. Нужные сторонние зависимости храни в проекте или в общем `_vendor` в корне проекта, без отдельных копий для каждой утилиты. Подключай `_vendor` относительно корня проекта.
- Документируй версии зависимостей и воспроизводимую команду установки. Не устанавливай пакеты автоматически при запуске скрипта.

## README

Пиши кратко и поддерживай README вместе с кодом. Укажи:

- назначение и ограничения утилиты;
- требования к Python и установку зависимостей, если они есть;
- рабочий каталог для команд и примеры запуска, включая `--help` и `--dry-run`, если он поддерживается;
- аргументы и существенные значения по умолчанию; для полного перечня можно сослаться на `--help`, не дублируя справку;
- входные и выходные файлы, базу относительных путей, поведение при повторном запуске и перезаписи.

## Проверка результата

- Запусти `--help` и проверь русский язык, полноту справки и отсутствие побочных эффектов.
- Проверь основной сценарий на небольших подходящих данных и затронутые ошибочные случаи. Для изменений файлов используй временную копию; одного `--dry-run` недостаточно для проверки записи.
- Если есть `--dry-run`, убедись, что он не меняет файлы и соответствует плану обычного запуска.
- При изменении путей или переносе проверь запуск из другого рабочего каталога и актуальность команд в README.
- Добавляй автоматические тесты для существенной логики и регрессий; не создавай тесты, которые лишь повторяют реализацию. В отчёте укажи выполненные проверки и то, что проверить не удалось.
