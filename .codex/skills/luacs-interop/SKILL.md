# LuaCs interop

Пиши контракт под установленный форк MoonSharp и LuaCs. База проверена для LuaCs workshop 1.0.117 (`c6e8829`) / MoonSharp (`b556e55`); это не обещание совместимости всех версий. [Версии и границы исполнения](references/validation.md).

## Рабочий алгоритм

1. Установи целевую сторону, DLL и commit. Различай бинарники в папке игры и workshop. Проверь включение C#, загрузку нужной сборки и точное полное имя типа. Наличие C#-исходника не доказывает его загрузку.
2. Проследи доступ: поиск `Type` → `LuaUserData.RegisterType` → descriptor → `CreateStatic` либо готовый экземпляр. Для собственных DTO регистрируй также вложенные и возвращаемые типы. Регистрация и запись глобальной переменной — разные действия. [Устройство моста](references/bridge.md).
3. Выпиши точные сигнатуры, направление передачи, допустимость null, владение коллекциями и объектами. Выбери конструктор, фабрику, заполнение свойств либо явный адаптер по [рецептам](references/contracts.md). `new`/`init` — обычные имена авторского API; механизм конструктора — `__new` и вызов static userdata.
4. Проверь преобразование каждого аргумента и результата, включая элементы коллекций, перегрузки и struct. Lua table не преобразуется автоматически в произвольный DTO. [Матрица типов](references/types.md).
5. Для callback установи конкретную сигнатуру, способ вызова, обработку ошибок, отписку и границу жизни Script. Произвольный `Action<T>`/`Func<T>` не возникает автоматически из Lua-функции. [Callbacks и загрузка](references/lifecycle.md).
6. Возьми минимальный связанный пример из [examples/bridge-demo](examples/README.md). Запусти подходящий host либо игру и пометь результат честно: E — исполнение, S — исходники, W — пример мода, D — документация, U — неизвестно. Для сбоев используй [диагностику](references/diagnostics.md).

## Правила решений

- Для нового управляемого API предпочитай небольшой DTO-класс с явными свойствами и метод без конкурирующих перегрузок. Фабрика полезна для инвариантов; она не нужна только ради доступности конструктора.
- Типизированный `Line[]` принимает плотную Lua-последовательность зарегистрированных `Line`. `object` принимает Lua table как `MoonSharp.Interpreter.Table`. `params Line[]` — отдельный случай; при передаче одним аргументом оберни настоящий массив.
- Различай Lua table-копию коллекции и userdata, удерживающую CLR-коллекцию. Не регистрируй общесистемные коллекции глобально без причины: это меняет представление и для других модов. Для локального требования типа используй `CreateUserDataFromType`.
- Для изменяемого struct прочитай копию, измени и запиши обратно через владельца; проверь результат. Для длительно живущих callbacks освобождай ссылки при остановке и не вызывай старый Script после reload.
- `Make*Accessible` нужен для конкретного закрытого API игры. Для собственных типов объявляй понятный публичный контракт. Наличие в `HasMember` не доказывает возможность записи или вызова.
- Внутрипроцессная ссылка на DTO не передаётся между клиентом и сервером. Сеть и сериализация требуют отдельного формата и проверки получателя.
