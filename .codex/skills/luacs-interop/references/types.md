# Типы и преобразования

Матрица относится к workshop MoonSharp `b556e55`; специальные преобразования LuaCs отмечены отдельно. E — изолированный host, S — исходники. [Полные источники](sources.md), [протокол](validation.md).

## Объекты и простые значения

| Возможность | Автоматическое поведение / настройка | Ограничение и выбор |
| --- | --- | --- |
| class | Зарегистрированный тип → userdata с исходной CLR-ссылкой; аргумент совместимого типа получает тот же объект. E/S M6, M7 | Регистрация вложенного/возвращаемого DTO нужна независимо от его использования в сигнатуре |
| struct | Getter/field/элемент возвращает упакованное значение; передача by-value копирует его. E/S M13, M14 | Изменение извлечённой копии не записывается в владельца. Сделай writeback; readonly-владелец может его запретить |
| Наследование | Стандартные отражённые публичные члены включают унаследованные; registry может выбрать descriptor базового класса. E/S M1, M11 | При fallback к базовому descriptor производные члены могут не быть видны; зарегистрируй конкретный тип |
| Интерфейс | `IsTypeCompatible` проверяет CLR-совместимость, аргумент реализации принимается как интерфейс. E/S M2, M6 | Явно реализованные члены не становятся публичными на классе автоматически; зарегистрируй интерфейс/предоставь фасад. Несколько интерфейсов могут дать composite descriptor (M11) |
| Поля и свойства | Чтение/запись через тип члена. Публичный getter без setter — чтение; readonly/const field — чтение. E/S M13, M14 | `MakePropertyAccessible` может открыть private setter; readonly field останется readonly. Это изменение общего descriptor |
| null / nil | CLR null → nil; Lua nil → null для reference/Nullable. E/S M6, M7 | nil для обязательного int — ошибка. nil для optional int использует default; optional string с явным nil получает null, а с пропущенным аргументом — default |
| Nullable<T> | Nullable разворачивается при конвертации; непустой CLR Nullable boxing даёт T, пустой — null. E/S M6 | Отличай `Nullable<T>` от игрового `Option<T>`; LuaCs регистрирует Option только для перечисленных T (P5) |
| string / bool | Нативные значения; числовые/boolean аргументы могут превращаться в string с невысоким весом. S M6, M7 | Строка `"3"` не универсальный ввод для int; `0` не bool. Для строгого контракта проверяй вход |
| Числа | Lua number — double. `NumericConversions` использует `Convert.ToInt32` и аналоги. E/S M9 | 2.5 → 2, 3.5 → 4: округление к ближайшему чётному, не усечение. Переполнение/NaN требует проверки. double теряет целочисленную точность выше 2^53 |
| ulong | LuaCs отдельно экспортирует ulong строкой и разбирает строку обратно. S P5 | Это поведение LuaCs, не чистого runtime; не превращай идентификатор в Lua number |
| Явные числовые обёртки | LuaCs `LuaInt32` и другие + соответствующие конвертеры дают типизированный аргумент; globals перечислены в LibShared. S P4, P5 | Применяй при реальной неоднозначности, сверив версию. Проще дать фасаду отдельное имя метода |
| Enum | Незарегистрированный enum → number; зарегистрированный → enum userdata. Число преобразуется в enum underlying type. E/S M6, M7, M11 | Число не проверяется на наличие именованного значения. `CreateEnumTable` перечисляет значения; его элементы тоже зависят от регистрации enum |

Строки таблицы ссылаются на разделы [M1–M20](sources.md#m1), [P4](sources.md#p4), [P5](sources.md#p5), [W2](sources.md#w2). Для `struct` рекомендуется отдельный setter/метод владельца, если состояние принадлежит игровому объекту. Не выводи из коробочного значения возможность менять память игры напрямую.

## Сигнатуры

| Сигнатура | Поддержка и синтаксис | Практическое ограничение |
| --- | --- | --- |
| Перегрузки | Вес аргументов, optional/params/ref и кеш. `Pick(3)` для int/double выбирает double. E/S M4, M6 | Это не C# compile-time resolution; плотность/элементы table не проверяются полностью при оценке кандидата |
| Optional | Пропущенный аргумент представлен Void → default. E/S M5, M6 | Явный nil и отсутствие аргумента не всегда равнозначны |
| `params int[]` | `Api.Sum(2, 3)`; либо один userdata, реально содержащий int[]. E/S M5 | `{2,3}` одним аргументом не разворачивается в params: ожидается один int. Обёртка через `CreateUserDataFromType` решает это |
| `ref/out` | Для `int RefOut(ref int x, out string s)` вызов `local r,x,s = Api.RefOut(3)` → `9,5,"out"`. E/S M5 | out-аргумент не подаётся. Lua-переменная сама не изменяется. Возвращаемое void занимает первый nil в tuple |
| Generic method | Форк создаёт GenericMethodMemberDescriptor; типовые аргументы идут перед обычными: `Api.Echo(Line, line)`. E/S M10 | `MakeGenericMethod` проверяет constraints. Нет полноценного повторного binder по закрытым типам: `Echo(Int32, 3)` падает, потому что 3 остаётся double. У экземплярных/optional/ref/params generic комбинаций есть отдельные риски; они не проверены целиком |
| Generic type | Закрытый CLR-тип можно зарегистрировать по полному имени. Регистрация открытого `List\`1` создаёт generator descriptor для закрытых типов. E/S M11, M20 | Открытый тип не является готовым конструктором `List<T>`. Для собственного T в динамической сборке проще фабрика `CreateList()` и регистрация возвращаемого закрытого типа на C# |
| Pointer / специальные типы | Method descriptor отбрасывает pointer-параметры и pointer-return. S M3, M10 | Не проектируй Lua API на pointer, Span/ref struct и иной CLR-специфике без отдельного адаптера и проверки; полноценная поддержка последних не установлена |

## Коллекции

**S/E:** [M6](sources.md#m6), [M7](sources.md#m7), [M8](sources.md#m8), [M2](sources.md#m2), [P1](sources.md#p1).

- Плотная table `1..Length` → одномерный `T[]`, `List<T>`, `IList<T>`, `ICollection<T>`, `IEnumerable<T>`: создаётся новый контейнер, каждый элемент преобразуется отдельно. Для DTO-элементов должны передаваться userdata, не таблицы полей. Отдельные строковые ключи последовательности игнорируются. Дыры/null требуют отдельного формата с длиной: Lua nil не сохраняется как обычный элемент.
- Table pairs → `Dictionary<K,V>` / `IDictionary<K,V>` с конверсией ключей и значений. Не выводи поддержку `IReadOnlyDictionary` или всех immutable-типов из поддержки Dictionary. LuaCs имеет точечные immutable-конвертеры; общей конверсии во все immutable-коллекции нет.
- Незарегистрированные `IList`/`IDictionary` при возврате становятся новыми Lua-таблицами. Индекс списка сдвигается на +1. Изменение таблицы не меняет CLR-контейнер; вложенный зарегистрированный class при этом может оставаться общей ссылкой.
- Зарегистрированная коллекция либо явная userdata-обёртка сохраняет CLR-контейнер. CLR-массив/List индексируется с 0; `Count`/`Length`, методы `Add`/`Remove` и индексатор определяются типом. Для dictionary доступ к ключу, совпадающему с именем члена, требует осторожности: используй явно доступный `get_Item`/`set_Item` либо фасад.
- `for value in clr_collection do ... end` использует `__iterator`/IEnumerable и даёт значения. Словарь может отдавать `KeyValuePair<K,V>`, для которого нужен descriptor. `pairs`/`ipairs` не являются универсальным API CLR-коллекции. Возвращённый незарегистрированный IEnumerable может стать iterator userdata, а не List.
- Изменение коллекции во время перебора регулирует сама CLR-коллекция. Для фильтрации/массовой записи безопаснее отдельный набор изменений либо метод C#.

**Пример:** сохранить тип массива при передаче в `object` или `params` без глобальной регистрации всех массивов:

```lua
LuaUserData.RegisterType("System.Type")
local descriptor = LuaUserData.RegisterType("BridgeDemo.Line")
local array = LuaUserData.CreateUserDataFromType(lines, descriptor.Type:MakeArrayType())
```

Здесь `lines` — плотная Lua table из `BridgeDemo.Line` userdata. `CreateUserDataFromType` выполняет `ToObject(Type)`, затем оборачивает результат; это не произвольный cast и не mapper table → DTO. Обёртка не восстанавливает связь с ранее скопированным контейнером. Для DTO-массива сохраняются ссылки на элементы, но создаётся новый массив.
