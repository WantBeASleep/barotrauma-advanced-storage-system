# DTO и выбор контракта

## Подходы

| Подход | Какую проблему решает и почему работает | Когда выбирать | Ограничение / альтернатива |
| --- | --- | --- | --- |
| `Line("steel", 2)` / `Line.__new(...)` | Запускает отражённый CLR-конструктор. S M1, M16; E | Небольшое число обязательных аргументов, понятный constructor | Перегрузки могут конкурировать; отдельная фабрика даёт уникальное имя |
| `Api.CreateLine(name, quantity)` | Обычный static method возвращает зарегистрированный DTO; валидирует инварианты. E/S M3, M7 | Недопустимое промежуточное состояние, ограничения, сложное создание | Это авторский API, его нужно определить в C#. `init` не особый механизм |
| `Request()` + свойства | Пустой constructor и setters проходят обычный descriptor. E/S M1, M14 | Много необязательных или именованных настроек | Возможен неполный объект; C# должен валидировать запрос перед использованием |
| `Api.LineFromTable(table)` | Аргумент типа `Table` принимается runtime напрямую; ваш код читает/валидирует ключи. E/S M6 | Удобный Lua-ввод, валидация исходного number до округления | Контракт зависит от MoonSharp; неизвестные ключи/отсутствие/версии схемы регулирует адаптер |
| Lua-адаптер table → DTO | Lua явно создаёт C# объекты и переносит поля; затем типизированный вызов | Lua-facing API с удобными именами, C# без зависимости от MoonSharp | Это дополнительный слой, нужны тесты преобразований; `CreateUserDataFromType` не заменит его |
| Custom converter | `Script.GlobalOptions.CustomConverters` регистрирует явное правило для DataType + CLR type. S P5, M6 | Повторяемый контролируемый контракт, где удобство оправдывает глобальную настройку | Влияет на другие вызовы/перегрузки; нужен жизненный цикл снятия/восстановления. Фасад часто проще |

Источники: [M1](sources.md#m1), [M3](sources.md#m3), [M6](sources.md#m6), [M7](sources.md#m7), [M14](sources.md#m14), [M16](sources.md#m16), [P5](sources.md#p5). Сравнение — рекомендации, выведенные из этих механизмов, а не ранжирование модов по популярности.

## Рекомендуемый минимальный контракт

1. Публичный DTO-класс с понятными типами полей: string, bool, ограниченные числа, вложенный class, `T[]`, `Nullable<T>` по необходимости. Класс удобен, когда Lua должен менять тот же объект; для снимка объяви копирование явно.
2. Отдельный C# метод обработки с типизированным `Request`, уникальным именем и возвращаемым `Result`. Он проверяет обязательные данные, диапазоны и элементы массива. При typed int дробность уже потеряна: если важно отвергать дроби, принимай double/Table на границе и валидируй до преобразования.
3. Зарегистрируй все участвующие DTO, включая созданные только C# результаты. Регистрация `Request` не регистрирует автоматически произвольные типы его свойств. Возвращать коллекцию таблицей или userdata — осознанный выбор. Для своего массива можно зарегистрировать `Namespace.Line[]`; для стандартной коллекции лучше избегать ненужного глобального влияния.
4. Определи владение. В примере `Result.Lines = request.Lines` намеренно разделяет массив с запросом; это не deep copy. Если нужен независимый снимок, создай новый контейнер и новые DTO-элементы. readonly property запрещает замену ссылки, но не обязана запрещать изменение объекта по этой ссылке.
5. Для результата «успех/ошибка» используй собственный стабильный result DTO, если коды нужны программно. Исключение + `pcall` подходит для неправильного использования, но не гарантирует структурированный error object.

**Пример:** [полный мод](../examples/README.md) задаёт `Address`, `Line`, `Request`, `Result`, фабрику и Table-адаптер. Lua создаёт запрос; C# считает Total; Lua читает вложенные данные. Никакой скрытой регистрации или зависимости на глобальный `new` нет.

## Данные в обратную сторону

Метод может вернуть class, массив, примитив или `Table`. Зарегистрированный class сохраняет CLR-ссылку; массив зависит от регистрации. Если C# создаёт Table, привяжи его к действующему Script, заполняй через `DynValue.FromObject(script, value)`/`table.Set`; сам факт создания Table не регистрирует вложенные объекты. Не переноси Table/Closure в другой Script после перезагрузки. **S:** [M7](sources.md#m7), [M19](sources.md#m19).

`object` полезен для непрозрачного контейнера, но скрывает контракт: Lua number станет double, Lua table — MoonSharp.Table. Если C# затем ожидает `(Line[])value`, типизированная обёртка обязательна. Лучше сделать параметр сразу `Line[]`, если полиморфизм не нужен. **S/E:** [M6](sources.md#m6), [P1](sources.md#p1).

## О производительности

По исходникам известны реальные операции: table → массив выделяет контейнер и преобразует элементы; CLR IList → table копирует контейнер; wrapper хранит CLR-ссылку; binder кеширует выбор перегрузки, а LazyOptimized компилирует вызов. Это позволяет избегать ненужных преобразований в частом цикле. Замеров времени/памяти здесь нет; утверждение «фабрика всегда быстрее конструктора» не обосновано. Для горячего пути сначала измерь нагрузку, затем рассмотри один пакетный C# вызов вместо множества мелких. **S:** [M3](sources.md#m3), [M4](sources.md#m4), [M8](sources.md#m8).
