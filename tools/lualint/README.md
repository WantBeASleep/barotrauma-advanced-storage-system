# lualint

Статическая проверка Lua-кода с помощью локального `bin/selene.exe`. Selene
запускается из корня проекта и использует `selene.toml` с единым std LuaCs
для клиента и сервера поверх встроенного `lua52`.

## Запуск

Нужны Python 3.7 или новее и `bin/selene.exe` (проверено с 0.31.0).
Дополнительные Python-пакеты не нужны.
Команды ниже выполняются из корня проекта.

Проверка Lua-кода в каталоге по умолчанию:

```powershell
python tools/lualint/lualint.py
```

Проверка отдельного файла или каталога:

```powershell
python tools/lualint/lualint.py Lua/Autorun
```

**Пример:** передача дополнительных аргументов Selene:

```powershell
python tools/lualint/lualint.py --selene-arg=--display-style --selene-arg=rich
```

Справка:

```powershell
python tools/lualint/lualint.py --help
```

## Параметры

- `targets`: необязательные пути к Lua-файлам или каталогам для проверки,
  отсчитываемые от корня проекта. По умолчанию: `Lua/`.
- `--selene-arg`: передать один дополнительный аргумент Selene. Для нескольких
  аргументов повторите параметр. Значения, начинающиеся с `--`, передавайте через `=`.
- `-h`, `--help`: показать справку и завершить работу.

## Входные данные и результат

- `Lua/`: каталог Lua-кода для проверки по умолчанию.
- `selene.toml`: правила проверки и выбранное описание API LuaCs.
- `selene_std_luacs.yml`: объединённые глобальные имена клиента и сервера,
  а также расширения стандартной библиотеки LuaCs.
- `bin/selene.exe`: исполняемый файл Selene.

Скрипт выводит диагностику Selene в консоль и возвращает его код завершения.
Исходные Lua-файлы не изменяются, в том числе при повторном запуске.

Пути вычисляются относительно расположения скрипта, поэтому его нужно сохранять
в `tools/lualint/lualint.py`. Относительные пути к проверяемым файлам всегда
отсчитываются от корня проекта, независимо от рабочего каталога при запуске.

## Границы проверки и обновление std

Selene обнаруживает неизвестные имена, случайные глобальные присваивания и обычные
ошибки Lua. Смешанные файлы с `if CLIENT` / `if SERVER` используют одно окружение;
сторону выполнения Selene не проверяет. Игровые объекты объявлены как `any`,
поэтому существование их методов, типы и сигнатуры также не проверяются.
Подробные аннотации и настройки Lua Language Server используются отдельно.

Штатные функции проверяются встроенным `lua52`; расширения `math`, `string`
и `debug` добавлены отдельными полями. Правила `undefined_variable`,
`unscoped_variables` и `incorrect_standard_library_use` включены.

После обновления аннотаций выполните отдельную команду (Python 3.9+):

```powershell
python tools/selene_std/generate_selene_std.py
```

Пути, ограничения разбора и `--dry-run` описаны в [README генератора](../selene_std/README.md).
Обычный запуск линтера не меняет std и не требует папок аннотаций.

Контрольные примеры с реальным Selene:

```powershell
python -B -m unittest discover -s tools/lualint -p 'test_*.py' -v
```
