# selene_std

Генерирует `selene_std_luacs.yml` из объединения `Library/Client` и
`Library/Server` проекта Barotrauma-Lua-Annotations. Нужен Python 3.9 или новее;
сторонних Python-пакетов нет. Формат проверен с локальным Selene 0.31.0.

## Запуск

Из корня проекта:

```powershell
python tools/selene_std/generate_selene_std.py --help
python tools/selene_std/generate_selene_std.py --dry-run
python tools/selene_std/generate_selene_std.py
python tools/lualint/lualint.py
```

По умолчанию источники находятся в соседнем `../Barotrauma-Lua-Annotations`,
результат — в корне мода. Эти пути вычисляются от расположения скрипта;
запуск из другого рабочего каталога поддерживается.

`--annotations-root КАТАЛОГ` задаёт корень аннотаций, `--output ФАЙЛ` — результат.
Переданные относительные пути отсчитываются от текущего рабочего каталога.
Обе папки сторон обязательны и должны содержать объявления в `.lua`.

Обычный запуск создаёт или заменяет выбранный YAML после проверки всех источников.
При совпадении содержимого файл не перезаписывается. Результат отсортирован,
записывается в UTF-8 с LF и не содержит времени или абсолютных путей.
`--dry-run` выполняет тот же разбор и сообщает о создании, обновлении либо
отсутствии изменений, не записывая файлы и не создавая каталоги.
Линтер автоматически std не регенерирует; обновляйте его после смены аннотаций.

## Правила извлечения

- Читаются все `.lua` обеих сторон, включая `Auto` и `Manual`.
- Глобальными считаются явные присваивания имени и объявления глобальных функций.
  `---@class`, `---@field`, локальные переменные, поля таблиц и имена на правой
  стороне присваивания не создают глобальных имён.
- `CS.Barotrauma.Type = {}` не создаёт глобальную `Type` или `Barotrauma`.
  Корневой `CS` берётся из собственного объявления. Локальные имена учитываются
  в пределах файла и блоков `do`.
- Одинаковые имена обеих сторон объединяются. Игровые глобальные объекты и
  функции получают только `any: true`, без сигнатур и ограничений стороны.
- Штатные имена и поля Lua защищены списками `STANDARD_GLOBALS` и
  `STANDARD_LIBRARIES`. Они остаются во встроенном `lua52`; генератор не заменяет
  `math`, `string`, `table`, `bit32` и другие библиотеки на `any`.
  Дополнения из аннотаций, например `math.clamp`, `string.startsWith` и
  `debug.breakpoint`, записываются отдельными ключами с `any: true`.

Разбор рассчитан на декларативный формат текущих аннотаций: присваивания,
таблицы с именованными полями, пустые функции, `local`, `do`, `return` и комментарии.
Это не универсальный парсер Lua: неподдерживаемые конструкции останавливают
генерацию с указанием файла и строки до записи YAML. При изменении формата
источников адаптируйте парсер и тесты. При смене базовой версии Lua проверьте
списки защищённых имён.

Сторона исполнения, игровые методы и их сигнатуры остаются вне проверки Selene;
подробные типы использует Lua Language Server. Его настройки генератор не меняет.
Состав доступных имён определяется предоставленными аннотациями, а не проверкой
живого окружения игры.

Формат YAML: [документация Selene](https://kampfkarren.github.io/selene/usage/std.html).
Штатные имена: [Lua 5.2](https://www.lua.org/manual/5.2/manual.html#6) и
[встроенные std Selene 0.31.0](https://github.com/Kampfkarren/selene/tree/0.31.0/selene-lib/default_std).

## Проверки

```powershell
python -B -m unittest discover -s tools/selene_std -p 'test_*.py' -v
python -B -m unittest discover -s tools/lualint -p 'test_*.py' -v
```

Первый набор проверяет генерацию на временных аннотациях обеих сторон:
отбор имён, дедупликацию, повторяемость, запись, `--dry-run`, ошибочные источники
и запуск из другого рабочего каталога. Второй запускает настоящий Selene
через проектную обвязку на положительных и отрицательных Lua-примерах.
